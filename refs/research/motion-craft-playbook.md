## 1. Движение в числах

### 1.1 Кривые и пружины

**Пружины движка** (`SP`, CM `references/motion-language.md` §1):

| Пресет | Параметры | Перелёт | Успокоение |
|---|---|---|---|
| `pop` | r 0.46, z 0.62 | 8,4 % | 0,44 с |
| `popS` | z 0.72 | 3,8 % | 0,38 с |
| `hl` | z 0.75 | 2,8 % | — |
| `snap` | z 0.85 | 0,6 % | 0,20 с |
| `move` | r 1.05, z 1 | 0 | 0,97 с |
| `tuck` | r 0.8, z 1 | 0 | 0,74 с |
| `cam` | r 4.5, z 1 | 0 | 4,18 с |

**Сколько перелёта прилично** ⚠:
- HF: ζ 0.80–0.85 даёт перелёт 1–1,5 % («чувствуется, не видно»), ζ 0.6–0.7 — только игривый тон, ζ < 0.55 — нельзя (HF `skills/hyperframes-animation/adapters/gsap-easing-and-stagger.md`).
- HS: затухание ≥ 0.72, «крошечный перелёт, никогда мультяшный отскок» (HS `SKILL.md` §9b).
- MM: перелёт есть у 8,8 % движений; одна заметная пружина на ролик (+4–6 %) (MM `references/motion.md` R1.10–R1.11).
- **Решение свода:**
  - по умолчанию `popS`/`hl` (z ≥ 0.72);
  - `pop` (8,4 %) — только герой, 1–2 раза за ролик;
  - `hop` (12,6 %) — только персонаж;
  - у объектов, которые едут к соседям, перелёта нет (CM motion-language §1).
- Перелёт только на трансформациях, не на прозрачности (HF gsap-easing-and-stagger.md).

**Безье, если нужна кривая, а не пружина:**
- `(0.16, 1, 0.3, 1)` — посадка без отскока (RM `remotion-markup/timing.md`).
- `(.2,.7,.2,1)` — «уверенная» по умолчанию (HF `skills/embedded-captions/references/motion-vocabulary.md`).
- `(.77,0,.175,1)` — шторка 400 мс (там же).
- `(.7,0,.2,1)` — швейцарский щелчок без перелёта (LO `swiss-motion/STYLE.md` L40).
- `linear` «почти всегда ошибка» (HF motion-vocabulary.md). Исключения: камера и механика (HF gsap-easing-and-stagger.md).

**Направление:** вход — `.out`, уход — `.in`, перемещение — `.inOut` (HF `skills/hyperframes-creative/references/motion-principles.md`).

**Разнообразие:**
- В сцене не больше двух движений с одинаковым easing (CM motion-language §2; HF motion-principles.md).
- 3+ разных easing и направлений на сцену; запрещено «всё въезжает с y:30, opacity:0» (HF `…/references/video-composition.md`).

### 1.2 Длительность по размеру и событию

Медианы реальных роликов при 30 fps (MM motion.md §1.1):
- сдвиг 12к, масштаб 10к, поворот 11к, прозрачность 6к, блюр 7к;
- в целом медиана 10к = 0,33 с, края 6к–24к.

Длительность по «весу» элемента:

| Элемент | Длительность | Источник |
|---|---|---|
| мелочь: чип, бейдж, подпись | 0,15–0,3 с; пружина 0,37–0,51 с | HF motion-principles.md; gsap-easing-and-stagger.md |
| стандартный блок | 0,3–0,5 с; пружина 0,51–0,74 с | там же |
| герой, тяжёлый объект | 0,5–0,8 с; пружина 0,74–1,03 с; герой и знак 18–30к | HF; MM R1.9 |
| камера, медленный дрейф | 0,8–2,0 с | HF motion-principles.md |

Типовые события:
- Появление 0,24–0,45 с, уход 0,1–0,3 с (power4.in) (CM motion-language §2).
- MM: вход 12к, уход сдвигом 13–14к. MM R1.1 и CM сходятся в том, что уход не длиннее входа.
- Линия рисуется со скоростью 1000–1500 px/с; наконечник — после древка, 0,15–0,2 с (CM motion-language §2).
- SVG-штрих: 0,3–0,8 с на сегмент, следующий стартует на 70–80 % предыдущего (HF `rules/svg-path-draw.md`).
- Счётчик 1,2–2,5 с: быстрее 0,8 с читается как вспышка (HF `rules/counting-dynamic-scale.md`).
- Зум к цели 1,0–2,0 с: быстрее 0,8 с — телепорт, дольше 2,5 с — тянет (HF `rules/coordinate-target-zoom.md`).
- Самая медленная сцена ≈ в 3 раза медленнее самой быстрой (HF motion-principles.md).

### 1.3 Сдвиг между элементами (стаггер)

- Каскад однотипных — 1–3к с неровным шагом (например 3,2,2,2,2,2); каждое движение ≈ 2× шага; вся волна ≤ 0,6 с = 18к (MM R1.8, `references/slop.md` U8).
- HF: 0,04–0,08 с (≈1–2,5к), формула `min(0.06, 0.5/N)`; всю серию держать ≤ 500 мс; больше 9 элементов — шторка вместо каскада (HF `rules/spring-pop-entrance.md`, motion-principles.md).
- Наш движок: 0,06–0,15 с (2–4,5к); элементы, которые называет диктор, — по одному на слово, шаг 0,3–0,45 с (CM motion-language §2). Хелпер `stag(i, d, accel)` в `lab/js/lab.js`.
- Перед ключевым словом пауза на 3–4к длиннее остальных (MM slop.md B5).
- Запрещено: ровный стаггер 0,1 с; «24 px, блюр 4–6 px, 40–80 мс на каждом тексте» (MM slop.md M4).
- Первое движение сцены — через 0,1–0,3 с после её начала: старт в t=0 читается как рывок (HF motion-principles.md).

### 1.4 «Быстро прилетает — мягко садится»

- Профиль `snapSettle`: к 10/25/50/75 % времени пройдено 54/84/96/98 % пути. Фирменный вариант: 60–72 % пути за первые 4–5к, потом хвост 0,4–0,6 с (MM motion.md §2, slop.md M1).
- В нашем движке ближе всего `ease.outExpo` и `ease.out4` (`lab/js/core.js`). Готового `snapSettle` нет (см. §9).
- «Быстро вошёл и держится, а не быстро вошёл и исчез» (BR `skills/brag/SKILL.md`:162).
- Короткая подпись (1–3 слова) стоит неподвижно ~0,8 с; фраза — 0,3 с на слово, минимум 1,2 с (BR `references/step-2-plan.md`).
- Формулировка для промпта: «arrive fast, land soft… nothing ever freezes (slow push on every hold); stagger 2–4 frames; blur only on fast moves» (`refs/research/opus-videos-analysis.md`, раздел A, п. 8).

### 1.5 Паузы без замирания

- Медленный наезд на паузе, разные значения по источникам:
  - 2–3 % (CM motion-language §2, §6);
  - 3–5 % (EK `references/motion-grammar.md`);
  - масштаб 1→1,04 за бит (HF motion-principles.md);
  - «ползучесть» 2–5 % (LO `satellite-briefing/STYLE.md` L47).
- На каждом удерживаемом кадре что-то живёт: дрейф 1–3 px/к (фон 1,1–1,5 px/к) или ползучесть масштаба 0,5–1 %; камера не медленнее ~1 px/к (MM slop.md M5, motion.md R6.14).
- Сколько неподвижности допустимо:
  - полная неподвижность ≤ 0,6 с (EK `references/quality-bar.md`);
  - ≤ 1 с (HS §1, LO satellite-briefing L48);
  - проверка HF `motion_frozen` падает после 2 с (HF `skills/hyperframes-cli/references/lint-validate-inspect.md`);
  - суммарно не больше ~1 с замирания на 30 с (EK).
- ⚠ Честная пауза:
  - MM: только после кульминации, 0,5–1,0 с (цифра-герой — 1,2 с);
  - SC: ключевую информацию держать неподвижно ≥ 1 с (SC `references/aesthetic-rules.md` R1/R2).
  - **Решение свода:** цифру-итог держать по SC, но с наездом 2–3 % — тогда она и читается, и живёт.
- Живость на паузе (HF `rules/sine-wave-loop.md`):
  - масштаб 0,008–0,015;
  - y 2–3 px;
  - поворот ±0,3–0,8° — редко.
  - «Лучше без движения, чем плохое движение»: плавающие «скринсейверы» — провал (HF `skills/faceless-explainer/references/motion-language.md`).

### 1.6 Размытие движения (motion blur)

- Наш рендер (CM `references/render.md` §3):
  - 16 подкадров, затвор 180°, усреднение `tmix`;
  - 4 подкадра — только черновик (быстрое движение идёт «ступенькой»);
  - статичные части не мылятся.
- Где нужно больше подкадров:
  - на самом быстром взмахе 10 подкадров дали «гребёнку», понадобилось 24 (EK `references/product-hero-realism.md` §3);
  - адаптивно: ≤ 20 px/к → 4, иначе ceil(px/5), до 64 (HS §9c).
  - **Решение свода:** на взмахах быстрее ~80 px/к проверять кадр на гребёнку и поднимать SUB.
- Где блюр нужен: только на «ударных» битах — удар, whip, переброс, вращение, масштабный пинок.
  - Нужен на 1–3 таких битах за ролик (HF `skills/hyperframes-animation/references/motion-blur.md`).
  - «Размой подлёт, посади резко»: не на тексте, который читают в этот момент, и не на дрейфе или параллаксе (там же).
- Блюр не должен пересекать жёсткую склейку (CM render.md §3; HS §9c).
- Одна грамматика размытия на весь ролик: мазок, чёткие шаги или затвор — не смешивать (MM R4.1).

## 2. Камера и монтаж в 2D

### 2.1 Движения камеры

| Приём | Числа | Источник |
|---|---|---|
| Медленный наезд | конечный масштаб 1,08 / 1,12 / 1,18 (тонко / норма / смело) | HF `registry/components/push-in/push-in.html`:141 |
| Многофазная камера | 0,88–0,96 → 0,98–1,02 → 1,04–1,15; дрейф 2–8 px по x, 1–4 px по y; без пружин | HF `rules/multi-phase-camera.md` |
| Рывок-наезд | медиана 1,46× за 10к; 6к → 1,25×; 12–18к → 1,4×; 20–45к → 1,5× | MM motion.md §6.5, R6.12 |
| Отъезд-раскрытие | ≈1,8× | MM R6.12 |
| Крэш-зум | 6к ease-in (1→2,6), отскок 3–6 % за 5к; держать ≥ 30к до и ≥ 45к после | SC `references/shots/camera/crash-zoom-punch.md` |
| Зум к цели | 1,5× умеренно, 3× доминирует; старт через 0,5–1,5 с после посадки раскладки; задержка ≥ 1 с | HF `rules/coordinate-target-zoom.md`, `rules/viewport-change.md` |
| Зум | только в логарифмическом масштабе; не «туда и сразу обратно» подряд | CM `references/engine.md` §9; HS §2 |

Параллакс слоёв:
- Скорости в коде компонента: дальний 0,35, средний 0,65, передний 1,12 от скорости камеры (HF `registry/components/scroll-camera-story/scroll-camera-story.html`:657–659).
- Соседние слои различаются по скорости в 2–2,4 раза; часть слоёв не масштабируется (MM R6.5).
- Ночной город с боковым проездом — 3–4 плана (LO `cel-anime-80s/STYLE.md` L56).

Whip-pan:
- Медиана 8к, пик скорости при t≈0,25. Склейка — на пике скорости; следующий план продолжает тот же вектор (MM motion.md §6.4, R6.9).
- CSS-рецепт (HF `skills/hyperframes-creative/references/beat-direction.md`:95): выход `x:-400`, блюр 24 px, 0,3 с power3.in; вход 0,3 с power3.out.
- В компоненте блюр ограничен 16 px (HF `registry/components/whip-pan-cut`).
- Жёсткий перенос камеры с блюром — не дольше 0,4–0,6 с (CM motion-language §6).

Match cut:
- Жёсткая склейка посреди движения, объект переходит в следующий план; позиция совпадает с точностью 0,03 кадра (MM slop.md X1–X8).
- Следующий план уже движется: 105–280 px на первом кадре (там же).
- Вариант «нырок логарифмическим зумом + match cut» (LO `dark-keynote/STYLE.md` L52–67).

Ведение объекта камерой:
- В ролике №2 «камера ведёт машину» вытянула кульминацию с 5 до уровня первой половины (P2 `REPORT.md`, приёмка v7).
- Камера никогда не стоит; ключи — гладкий сплайн (LO `lidar-survey/STYLE.md` L48).
- Тряска:
  - на светлых интерфейсах не нужна, в тёмном атмосферном — ≤ 0,02 (SC aesthetic-rules.md Q3);
  - ударов всем кадром (пинок масштаба, тряска, вспышка) ≤ 3 на ролик, ≥ 16 долей между ними (SC R4).

### 2.2 Ритм на 35–45 с

- Новое событие каждые 1,5–3 с, микрособытие (подсветка, тик) — каждые 0,5–1 с (CM motion-language §2).
- Хук ≤ 2 с (CM `SKILL.md` принцип 6).
- Длина «бита» в 39 человеческих роликах: p25/p50/p75 = 1,0 / 1,65 / 2,38 с (MM `library/moments.jsonl`; это строки «не проверены», не главнее чисел из `references/`).
- Смысловые биты 3–7 с, не длиннее 7,5 с (MM `references/director.md`). Внутри бита склейки каждые 0,3–2,3 с; сцены к концу укорачиваются, последняя задерживается (MM `references/transitions.md` R3.2.2).
- На 45–60 с: 10–12 битов, одно доказательство на 8–10 с (MM director.md, «практика»). 30-секундный фильм — 12–15 композиций (EK motion-grammar.md).
- **Для 40 с:** 6 смысловых битов (бриф GTA, `refs/research/ideas-2026-10-22.md` L57) × 2–4 визуальные мысли = 14–20 смен картинки, по одной на 2–3 с.
- Структура 40 с из ролика №2: «0–1 хук · 1–8 потолок · 8–22 механизм · 22–31 полёт · 31–38 показано/обещано · 38–40 петля» (`refs/research/tesla-roadster-motion.md` L321).
- **Кульминация сильнее начала** (урок P2):
  - самый крупный план;
  - единственный крэш-зум или удар всем кадром;
  - единственная «фирменная» пружина;
  - перед самым большим движением музыку убрать на 8–15 дБ на 0,2–0,5 с (MM `references/sound-sync.md` §6a).

### 2.3 Переходы: что работает и что дёшево

Работает в объяснениях:
- Жёсткая склейка за 0,05–0,1 с до фразы (CM motion-language §4).
- «Продолжение»: объект остаётся и перестраивается (там же).
- Срез кривой: выход `x 0→−230` power4.in, вход `+230→0` power4.out, 0,2–0,4 с; выход гаснет к 25–30 % пути (HF `skills/faceless-explainer/references/cut-catalog.md`).
- Зум насквозь (HF cut-catalog.md):
  - выход 1→1,2, блюр 0→10 px, 0,2 с;
  - вход 0,75→1, expo.out 0,5 с;
  - блюр на тексте ≤ 10 px, на всём кадре 18–20 px.
- Склейка-скан или раскрытие сканом: две копии сцены и `clipPath` по линии (CM engine.md §9). Для GTA это «конус взгляда».
- «Смена времени — скан, а не растворение» (LO satellite-briefing L47).

Дозировка:
- Один основной переход на 60–70 % склеек и 1–2 акцентных (HF `skills/hyperframes-animation/transitions/overview.md`).
- На весь ролик 2–3 типа переходов (HF faceless-explainer `story-design.md`:180).

Выглядит дёшево:
- Кроссфейд двух плотных раскладок — «грязная двойная экспозиция» (CM motion-language §4; MM slop.md).
- Белая вспышка или провал в чёрное между битами (MM slop.md). В движке белая вспышка допустима максимум на 1–2 главных ударах (CM).
- Шторка или круг между каждым битом (MM slop.md).
- Видимые повторяющиеся сетки, плитки, соты; звёздная диафрагма, блик-линза, «петля» (HF transitions/overview.md).
- Переход тёмное ↔ светлое через серое (CM motion-language §10).

Допустимые исключения (MM slop.md A1–A6):
- одна 50-процентная двойная экспозиция в 1 кадр на ролик;
- серый провал 4к, если он несёт действие.
- На склейке не больше 3 пустых кадров; уход и вход перекрываются на ~2к.

## 3. Композиция 9:16 на весь кадр

### 3.1 Безопасные зоны, 1080×1920 (CM `references/social.md` §2)

| Площадка | Верх | Низ | Слева | Справа |
|---|---|---|---|---|
| Reels | 269 | 672 | 65 | 65 + колонка кнопок |
| Shorts | 288 | 672 | 48 | 192 |
| TikTok | 240 | 660 | 120 | 120; колонка кнопок 180 px с y = 840 |

- **Общая зона для текста:** x 120–888, y 288–1248; ниже y = 840 правый край — x 780 (`window.SAFE`, проверка `tools/safecheck.mjs`).
- **Зона только для текста.** Картинка (не текст) может и должна выходить за неё (CM social.md §2).
- ⚠ В v6 ролика №2 субтитры стояли на y ≈ 1396 (SAFE y 250–1450), и это приняли (P2 `PROGRESS.md`). Это ниже строгой границы Reels/Shorts 1248, поэтому до публикации — проверка на телефоне.
- Жёсткий потолок по HF: не заходить в нижние 22 % (y > 1498) (HF `skills/embedded-captions/references/composition-craft.md`:450,488).

### 3.2 Как занять весь кадр (урок P2: сцены жили в верхних ~60 %, снизу пусто)

- **Три плана всегда:** дальний, средний и передний, ≥ 3 слоя глубины (HF faceless-explainer `references/visual-design.md`). У hologram-hud: сетка, предмет, HUD (LO `hologram-hud/STYLE.md` L12).
- **Главный объект:**
  - 40–60 % кадра, главный визуал ≥ 40 % (HF visual-design.md);
  - 60–85 % полезного кадра (EK motion-grammar.md);
  - ≥ ⅓ высоты кадра (LO hologram-hud L69, satellite-briefing L64).
  - Читаемый объект-доказательство ≥ 0,55 ширины = ≥ 594 px (MM slop.md G1).
  - Машина шириной ≈ 235 px получила 6/10 со словами «машина мелкая» (P2 `reviews/razbor_video_v4_A.md`).
- **Низ кадра (y 1248–1920) — не пустота, а:**
  - земля и мокрый асфальт с отражением — перевёрнутая размытая копия (LO `cel-anime-80s/STYLE.md` L9, L22);
  - передний план в расфокусе, уходящий за край;
  - продолжение героя.
- В эту зону — только то, что не нужно читать (CM social.md §2).
- **Вылет за край:** обрезать содержимое краем можно, текст и подписи — нет; внешние 12 % по краям свободны от текста (MM `references/layout.md`). Тег «bleed-off-edge» — у 29 приёмов из человеческих роликов (MM moments.jsonl).
- **Иерархия:** ≥ 2 различия из «размер 3:1 / вес 800 против 400»; ≥ 3 разных крупности на ролик (HF visual-design.md).
- **Не больше 2 целей для чтения одновременно** (EK motion-grammar.md) и ≤ 3 групп внимания (MM slop.md E2).
  - В P2 было 5 блоков текста сразу, сцена получила 6,5/10 (P2 razbor_video_v4_A.md).
  - Вторая панель допустима, только если одна больше другой по площади в ≥ 2 раза (MM slop.md G4).
- **Без широких двойных и тройных экранов** — складывать по вертикали (HF visual-design.md:92–99).

### 3.3 Где держать главный объект и текст

- Герой — центр по y ≈ 0,30–0,40 H = 576–768 px; подписи — y 0,62–0,70 H = 1190–1344 px. Это «практика, не из выборки» (MM layout.md §10).
- ⚠ HF: герой высоко, 0,2–0,35 H (HF `skills/hyperframes/references/frame-worker-core.md`:50) или по центру, ≈ 0,42 H = 806 px (HF visual-design.md:97).
- Раскладка навыка (CM social.md §3):
  - сцена y 300–830;
  - плашка y 840–1080;
  - субтитры y 1110–1240;
  - общий левый край x = 120.
  - Урок P2: картинку опустить и укрупнить (v6 — SAFE y 250–1450).
- Крупный заголовок: линия ≤ 0,8 W = 864 px, 2–3 строки (MM layout.md §10). HF: текст-герой — 60–80 % ширины (HF video-composition.md).

## 4. Премиальное 2D против дешёвого

> ⚠ **Главный риск ролика №3.** Наша палитра — почти чёрный фон, золотое пятно, радиальное свечение — дословно совпадает с «премиальной пастишью»: near-black ground, radial glow, gold spark, lens flare (MM slop.md #4, N11, N12).
> - В 6 из 10 ИИ-роликов фон почти чёрный, у людей — меньше трети (MM `references/judgment.md`).
> - HF относит неон и «голубое на тёмном» к приметам ИИ (HF `…/references/house-style.md`).
> - **Выход:** каждый свет мотивирован миром (окно, вывеска, фара, конус взгляда), загорается событием, а тёмный фон всегда структурирован городом, а не пустотой.

### 4.1 Свет, свечение, градиенты

- **Свет как в студии:** один ключевой свет, контровой, спад и контактная тень. Свечение на каждом элементе выглядит дёшево (MM `references/world.md`).
- **Свечение (сколько):**
  - пиковая прозрачность 0,15–0,30, **жёсткий потолок 0,45**;
  - ореол выходит за объект на 200–450 px;
  - расцвет 0,6–1,4 с, совпадает с посадкой героя;
  - «дыхание» 2,5–4 с;
  - не ставить box-shadow и ореол на один элемент (HF `rules/ambient-glow-bloom.md`).
- **Ореол как событие:** пик ~35 px блюра при 40 %, гаснет за ~0,3 с (MM slop.md K3).
- **Свечение (где):**
  - только от излучающих объектов; слабое — от цвета ярче ~0,9;
  - самый широкий ореол подкрашен в тёплый (халация);
  - силуэты штампуются чёрным в слой свечения, «чтобы свет не просвечивал сквозь них» (LO cel-anime-80s L24);
  - «нет свечения, кроме фронта» скана (LO lidar-survey L12, L26).
- **Неоновый контур** 2–4 px, обводки 2–3 px при 1080p (LO cel-anime-80s L18).
- **Градиенты:**
  - полноэкранный линейный градиент на тёмном фоне даёт полосы в H.264 — брать радиальные (HF video-composition.md);
  - фон «никогда не чистый чёрный и никогда не градиентное небо» (LO lidar-survey L30);
  - подъём света сверху по центру + виньетка углов 50–55 % (LO dark-keynote L16).
- **Блик или проход света:** не больше одного на план, только на герое, обрезан по его форме (SC aesthetic-rules.md Q4); блик ≤ 20 %, ≤ ~1,3 с (LO dark-keynote L88).
- **Света в кадре — способ раскрытия:** неосвещённое — «несколько процентов» яркости (LO dark-keynote L18–20). «Двигай свет, а не рисунок»: полосы света едут по неподвижному объекту (LO cel-anime-80s L42–46).

### 4.2 Тени, глубина, воздушная перспектива

- Тень карточки ≤ 12 % (MM slop.md D3); в нашем рисованном языке тень — смещённая цветная подложка, не фильтр (CM motion-language §8).
- **Воздушная перспектива:** прозрачность по глубине — ближнее яркое, дальнее ~25 % (LO hologram-hud L20). Ночью насыщенность ниже (LO `tilt-shift/STYLE.md` L16).
- **Глубина резкости:**
  - 3–6 px блюра на шаг глубины, максимум 8/16/24 px;
  - затемнение дальнего 0,55;
  - перевод фокуса 0,5–1,2 с (HF `rules/depth-of-field-blur.md`).
- Поверхности (LO dark-keynote L18–20):
  - 3 ступени тёмных поверхностей;
  - рамка 1 px ≈ 8 % белого;
  - внутренний верхний блик 1 px.

### 4.3 Зерно, текстура, линии, детализация

- **Зерно:** одно значение на весь ролик, ≈ 0,03, против полос; не ради «глубины» (MM world.md §5, slop.md N20). Пресет HF — 4 % (HF `frame-presets/capsule/FRAME.md`:108). У dark-keynote «без зерна» — выбрать одно.
- **Запрет на «призрачный декор»:** гигантский текст при 3–9 %, линии в 1 px, сетки, зерно как имитация глубины (MM slop.md N20). Декор при 12–25 % ещё работает, ниже 10 % его не видно (HF video-composition.md).
- **Линии:**
  - одна толщина, один радиус и одна логика света на весь ролик (MM judgment.md #7);
  - рамки на видео 2–4 px (HF video-composition.md);
  - тонкие метки 1,2–2,6 px с тёмным ореолом (LO satellite-briefing L22);
  - каркас ~1,3 px с аддитивным сложением (LO hologram-hud L20).
  - «Кривые палочки» в P2 (лишние потомки SVG) убирали отдельно (P2 PROGRESS.md).
- **Детализация:**
  - деталь мельче ~24 px считается нечитаемой (HF `skills/hyperframes-registry/references/component-quality-bar.md`);
  - вентилятор 70 px и частицы 10 px критик назвал «мелкими» (P2 razbor_video_v4_A.md);
  - частиц 10–18 для хлопка, 24–40 для распада, потолок ~40, у каждого всплеска есть причина (HF `rules/particle-burst.md`).
- **Не кипеть:** seed контура фиксирован; «живую» линию менять ступенькой раз в 4–6к (CM engine.md §4).
- **Реалистичные люди и города кодом** выглядят хуже графики (CM motion-language §10). Город рисовать графично: силуэты, окна, свет — не фотореализм.

### 4.4 Цвет

- Один акцент с одним смыслом плюс не больше одного сигнального цвета (MM slop.md K1, D1).
  - «Если два предмета акцентного цвета — один лишний» (LO dark-keynote L24–28).
  - Акцент тратится только на зафиксированное значение и становится акцентом в кадр, когда оно стало правдой (LO hologram-hud L29–31).
- Для ролика №3: `#FFC83D` — единственное «важное сейчас» (конус взгляда, найденное, цифра). Неон города — приглушённые холодные тона, не второй акцент. Ближайшая демо-палитра — satellite-briefing: отметки `#F2F5F6`, показание `#FFBE55` (LO satellite-briefing L29–35).
- Нейтральные тона подкрашены к акценту, без чистых #000 и #fff (HF house-style.md). Нейтральные — «чуть синие, никогда не тёплые коричневые» (LO dark-keynote L24).
- Не уводить чёрное прямо в акцент — двигать акцентный элемент между состояниями (opus-videos-analysis.md, раздел A, п. 9). Подкраска при появлении сходит к основному цвету за 1–6к (MM slop.md D2).
- Запрещённые «шаблонные» hex: #7c3aed #2563eb #6366f1 #8b5cf6 #a855f7 #4f46e5 (HF `…/placeholder-material.md`:144). Радужные шкалы высот нельзя (LO lidar-survey L30–36).

## 6. Звук под картинку (коротко)

- **Сведение:**
  - −14 LUFS, TP ≤ −1 dBTP (CM `references/audio.md`; MM sound-sync.md);

## 7. Запреты: приметы ИИ-вида и дешёвого 2D

1. Почти чёрный фон + радиальное свечение + золотая искра + блик-линза — «премиальная пастишь» (MM slop.md #4, N11–N12).
2. Свечение на всём; свечение > 0,45; box-shadow + ореол на одном элементе (HF ambient-glow-bloom.md; MM world.md).
3. Градиентный текст, полоска акцента слева, «голубое на тёмном», фиолетово-синие градиенты, одинаковые сетки карточек, всё по центру (HF house-style.md).
4. «Призрачный декор»: гигантский текст на 3–9 %, линии в 1 px, сетки, зерно ради глубины (MM slop.md N20); плавающие боке (HF visual-design.md:90).
5. Фальшивый HUD:
   - угловые подписи, «02 / X», «Chapter 3», BPM, таймкоды, версии (MM lint.mjs C1–C4; HS §8);
   - «no corner labels, no fake HUD numbers» (opus-videos-analysis.md, раздел A, п. 7);
   - HUD «шумит для нетехнической аудитории» (HF `registry/components/CATALOG.md`, telemetry-hud).
6. Карточка 0,3 W в пустоте; плоская заливка на сцену; > 3 разных фонов за ролик — это слайды (MM slop.md N4).
7. «Слайд-тест»: закрыть текст на листе из 16 кадров; если больше половины — «карточка на плоском цвете», это презентация (MM slop.md, часть 2).
8. Слайдшоу: всё показано в первые 25 % сцены, потом стоит (HF faceless-explainer motion-language.md).
9. Скринсейвер: всё плавает (там же).
10. Пружинистость по умолчанию — «отталкивает мгновенно» (там же); `back`, `elastic`, `bounce` — только в игривом тоне (HF gsap-easing-and-stagger.md).
11. Линейное движение; одно движение за раз; мёртвые биты (HS §8, §9b).
12. Ровный стаггер 0,1 с; одинаковое появление у всех элементов (MM slop.md M4; HF video-composition.md).
13. Кроссфейд плотных раскладок, белые вспышки, провалы в чёрное, шторка между каждым битом (CM; MM slop.md).
14. Мелочь: деталь < 24 px, герой < ⅓ высоты, 5 блоков текста сразу (HF component-quality-bar.md; LO hologram-hud L69; P2).
15. Пустой низ кадра, сцена в верхних 60 % (P2 REPORT.md).
16. Масштаб только текстом. Нужны линейка, люди-силуэты, земля, сравнение рядом (P2 REPORT.md; HF radial-surround / overwhelm-surround).
17. Кипящие контуры (новый seed каждый кадр), двойной штрих rough.js на рисующейся линии (CM engine.md §4).
18. Выдуманные цифры и «слоганы»: «Not just X. It's Y.», «Unlock», «the future of» (MM slop.md; BR slim.md). Для GTA: не «GTA 6 делает X», а «не рисуется» вместо «ничего нет» (ideas-2026-10-22.md L72–74).
19. Логотип, фирменный шрифт GTA, карта Vice City, кадры игры (ideas-2026-10-22.md L72–74). Вывески — общие слова, без брендов (LO cel-anime-80s L9).

## 8. Чек-лист визуального критика (для вставки в задание)

Проверять на листе из готового MP4 (кадр каждые 0,5 с) и на кадрах середин переходов. Порог в скобках.

1. **Хук:** в первые 1,5 с крупный объект и действие с первого кадра; кадр 0 не пустой (CM qa.md §5).
2. **Заполнение:** главный объект ≥ ⅓ высоты; ≥ 3 плана; низ (y 1248–1920) занят картинкой, а не пустотой (§3.2).
3. **Мелочь:** нет детали < 24 px, которую надо разглядеть; подписи ≥ 24 px, субтитры ≥ 56 px (§5).
4. **Безопасная зона:** весь текст в x 120–888, y 288–1248 (ниже 840 — x ≤ 780), иначе пометка «проверить на телефоне» (§3.1).
5. **Чтение:** ≤ 2 цели для чтения одновременно; заголовок не повторяет субтитр; ≥ 0,35 с на слово (§3.2, §5).
6. **Контраст** текста ≥ 4,5:1; непроизнесённые слова ~3:1 (§5).
7. **Без звука понятно:** смысл каждой сцены читается по картинке и субтитрам (§5).
8. **Ритм:** новая визуальная мысль каждые 2–3 с; полной неподвижности > 1 с нет; паузы с наездом 2–5 % (§1.5, §2.2).
9. **Посадки:** движения быстро входят и мягко садятся, без мультяшного отскока; перелёт > 4 % — не больше 2 на ролик (§1.1, §1.4).
10. **Разнообразие:** в сцене ≥ 3 разных появления; стаггер неровный, волна ≤ 0,6 с (§1.3).
11. **Переходы:** в серединах переходов нет двойной экспозиции и каши; ≤ 3 типа переходов на ролик (§2.3).
12. **Блюр:** размыт подлёт, посадка резкая; нет гребёнки на быстрых взмахах; текст в момент чтения не размыт (§1.6).
13. **Масштаб:** величина показана картинкой (линейка, люди, сравнение), а не только числом (§7, п. 16).
14. **Кульминация:** самый крупный план и единственный удар всем кадром приходятся на главный момент, не на начало (§2.2).
15. **Свет:** каждое свечение имеет источник в мире; пик ≤ 0,45; свечение — событие, а не постоянный фон (§4.1).
16. **Акцент:** `#FFC83D` в кадре означает одно «важное сейчас»; второго акцентного предмета нет (§4.4).
17. **Глубина:** дальнее темнее, бледнее и мягче ближнего; параллакс планов заметен при движении камеры (§2.1, §4.2).
18. **Единство:** одна толщина линий, один радиус, одна логика света; контуры не кипят (§4.3).
19. **Без ИИ-примет:** ни одного пункта из §7; слайд-тест пройден (≤ ½ кадров — «карточка на плоском цвете»).
20. **Стоп-кадр:** любой кадр из середины сцены можно выложить постом (CM motion-language §9).

**Оценка сцены 1–10.** Опора: HS — сцены ≤ 7 исправлять, ≥ 9 не трогать (HS §9b); оценки и формулировки P2.
- **6** — читается, но выглядит наспех: объект мелкий (герой < ⅓ высоты, детали 10–70 px), 4–5 текстовых блоков сразу, полкадра пусто, масштаб только числом, 1–3 с почти статики. Так оценили «карточки» и «поворот мира» в P2 v4.
- **8** — одна ясная мысль крупно: формула или цифра с действием (P2 «1 М² ≈ 10 Т» с отсчётом 9→10 — 8/10); кадр заполнен, переходы чистые, ритм ровный. Из претензий — 1–2 мелочи вкуса: отдельная подпись, неидеальный свет.
- **10** — уровень студии:
  - каждый стоп-кадр — постер, все пункты чек-листа пройдены;
  - свет мотивирован, глубина в 3+ плана, движение с весом и мягкой посадкой;
  - смысл понятен без звука; ничего нельзя убрать.
  - В P2 до 10 не дошла ни одна сцена; максимум — 9 (призыв в v6).
- **Порог сдачи** — каждая сцена ≥ 8 (P2 PROGRESS.md: «≥8 по каждой сцене»).
- **Формат отчёта** — до 25 строк, проход до ~30 мин, ≤ 12 полноразмерных кадров (CM `references/process.md` §3).

### Не хватает для правдоподобного ночного города

В движке нет ни одного SVG-фильтра (`feGaussianBlur` в `core.js` — 0 вхождений).

1. **Свечение и bloom:** слой излучения (окна, вывески, фары), размытый в 2–3 прохода; силуэты штампуются чёрным поверх; потолок 0,45 (LO cel-anime-80s L24; HF ambient-glow-bloom.md; LO hologram-hud L20 — «два прохода свечения»). Стоимость `feGaussianBlur` × 16 подкадров на 1080×1920 — {{проверить}} на черновом рендере.
2. **Туман и дымка:** слои радиальных градиентов + `fbm1` с медленным дрейфом; плотность растёт с глубиной. Компонента «fog» нет ни в HF, ни у нас (разведка HF CATALOG) — числа {{проверить}}.
3. **Отражения на мокром асфальте:** перевёрнутая, размытая, растянутая копия слоя излучения, полосы по вертикали (LO cel-anime-80s L9, L22). Заодно закрывает пустой низ кадра.
4. **Объём и перспектива:** нет риг-камеры с планами. Нужны слои со скоростями 0,35 / 0,65 / 1,12 (HF scroll-camera-story) и CSS-перспектива 700–1400 px (800–1200 при движении камеры) (HF `rules/3d-camera-flight.md`); либо 2,5D-масштаб `s = 1/(1/zoom − z)` (LO dark-keynote L18–20).
5. **Тысячи окон:** инстансинг по `hash01` с уровнями детализации — для сцены «дальние дома переключают 3 уровня детализации» (ideas-2026-10-22.md L66–68).
6. **Глубина резкости по слоям:** 3–6 px на шаг, максимум 8/16/24 px (HF depth-of-field-blur.md).
7. **Зерно и виньетка:** один оверлей, зерно ≈ 0,03 против полос на тёмных градиентах (MM world.md §5), виньетка 50–55 % (LO dark-keynote L16).
8. **Кривая «быстро прилетает — мягко садится»:** хелпер cubic-bezier, например `(0.16,1,0.3,1)`, или профиль `snapSettle` (MM motion.md §2). Сейчас есть только `outExpo`/`out4`.
9. **Конус взгляда / скан-фронт:** маска-сектор (`arcD` + `clipPath`), фронт со светлым швом, за фронтом блоки гаснут до контура (LO lidar-survey L22; ideas-2026-10-22.md L66–68). Приём «рентген сканом» в движке есть (CM engine.md §9) — расширить до сектора.
10. **Проход света** по неподвижному объекту: полоса-градиент в маске объекта (LO cel-anime-80s L42; SC Q4). Компонент HF `light-sweep-pass` — образец (Apache-2.0, код брать можно).
11. **Линии скорости и направленный блюр** только на whip-pan (LO satellite-briefing L25). Для whip-pan достаточно рендерного motion blur, отдельный хелпер не нужен {{проверить}} на гребёнку.
