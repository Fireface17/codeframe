# Prompt Builder — описание задачи → готовый промпт

Цель: выдать ГОТОВЫЙ к использованию промпт (system и/или user message) под конкретную задачу.
Модель по умолчанию — **Claude Opus 5.5** (`claude-opus-5-5`, effort `medium`): так сейчас советует
Anthropic для большинства задач. Fable 5.1 / Mythos 5.1 — для тяжёлых рассуждений и многочасовых
агентов; Sonnet 5.5 и Haiku 5.5 — когда важны скорость и цена. Не пересказывать теорию — выдавать
рабочий артефакт плюс короткое обоснование решений.

**Базовая установка:** промпты прежнего поколения на новых моделях работают без правок. Отличия
поведенческие и лечатся точечными блоками по симптому — не сваливать в промпт всё подряд.
Готовые блоки лежат в references этого скилла; их **копировать дословно** (они откалиброваны на
evals Anthropic, пересказ теряет эффект):

- `references/models-5-5-blocks.md` — Opus 5.5, Sonnet 5.5, Haiku 5.5 и таблица выбора модели/effort;
- `references/fable-5-1-blocks.md` — Fable 5.1 / Mythos 5.1;
- `references/video-templates.md` — шаблоны агентов для роликов: сессия производства, критик,
  независимый оценщик, ночной прогон.

## Шаг 0 — Классифицируй цель промпта

Определи из задания либо ОДНИМ точным уточнением (не анкетой):

1. **Поверхность**: system prompt продукта (multi-turn) · разовый user message · промпт для
   агента/harness · ТЗ для субагента · шаблон с переменными (`{{VAR}}`).
2. **Потребитель вывода**: человек в чате · программа (структурированный вывод) · файлы на диске.
3. **Горизонт**: single-turn · multi-turn · long-horizon агент (часы, несколько контекстных окон).
4. **Модель и effort.** По умолчанию Opus 5.5 (`medium`); Fable 5.1 (`high`) — для длинных
   рассуждений и многочасовых агентов, или когда Opus 5.5 на высоком effort не дотягивает;
   Sonnet 5.5 — агенты `medium`, чат `low`/`medium`; Haiku 5.5 — `medium`, массовые простые задачи.
   Если модель не указана — Opus 5.5, и сказать об этом в обосновании. Уровни разных моделей не
   равны — sweep на своих evals заново при смене модели; `xhigh`/`max` — только с измеренным
   выигрышем. Таблица — `models-5-5-blocks.md`, раздел A. Блоки берутся из reference своей модели.
5. **Обвязка** (для агентных промптов). API: поддерживает ли turn-scoped system messages,
   `thinking.display`, субагентов, правку истории. Claude Code: у субагента поля `model`, `effort`,
   `maxTurns`, `tools`, `omitClaudeMd`, `background`; у `claude -p` — `--max-turns`,
   `--max-budget-usd`, `--permission-prompts none` (`video-templates.md`, раздел 5). Часть
   симптомов чинится ТОЛЬКО обвязкой — такие пункты помечены `[harness]`, их надо назвать
   пользователю отдельно, а не маскировать текстом промпта.
6. **Готовый шаблон?** Промпт для производства ролика, критика, независимого оценщика или ночного
   прогона без присмотра — взять каркас из `references/video-templates.md` и заполнить, а не
   собирать с нуля.

Не хватает критичного (домен, формат вывода, аудитория) — один точный вопрос. Некритичное — разумный
дефолт плюс явный список допущений в конце.

## Шаг 1 — Собери ингредиенты контекста

Чек-лист (пропускай нерелевантное, не раздувай):

- **Роль** — одно предложение в system фокусирует поведение и тон.
- **Цель + мотивация (WHY)** — объяснять, зачем правило существует: модель обобщает из причины
  лучше, чем из голого запрета («ответ читает TTS-движок, поэтому без многоточий»).
- **Входные данные** — что придёт, откуда, в каком виде; для шаблонов — плейсхолдеры.
- **Формат и ДЛИНА вывода** — явно; effort видимый ответ не укорачивает, краткость задаётся
  только промптом.
- **Критерии успеха** — что считается хорошим ответом.
- **Ограничения** — формулировать ПОЗИТИВНО (что делать), а не только запретами.
- **Edge cases** — что делать при неполных/противоречивых входах.
- **Примеры (3–5)** — самый надёжный рычаг формата и тона: релевантные, разнообразные, в
  `<example>` внутри `<examples>`. Для задач с извлечением источников один полный пример с
  `<rationale>` — сам по себе рычаг (§7 библиотеки).
- **Инструменты/окружение** — какие есть, когда какими пользоваться.

## Шаг 2 — Структура промпта

Канонический порядок длинного system prompt:

```
[Роль — 1-2 предложения]
<context>       — фоновые знания, документы
<instructions>  — нумерованные шаги, если важен порядок/полнота
<examples>      — 3-5 штук в <example>
<output_format> — формат, длина, язык вывода
[короткое напоминание тона/краткости в самом КОНЦЕ длинного промпта]
```

- **XML-теги** для разнородных блоков — консистентные говорящие имена, вложенность по естественной
  иерархии.
- **Long context (20k+ токенов)**: длинные документы — В НАЧАЛО, вопрос и инструкции — В КОНЕЦ
  (до +30% качества). Каждый документ в
  `<document index="n"><source>…</source><document_content>…</document_content></document>`.
- **Quote grounding**: по длинным документам — сначала «выпиши релевантные цитаты в `<quotes>`»,
  затем ответ на их основе.
- **Стиль промпта заражает вывод**: нужна проза без markdown — писать сам промпт прозой без markdown.
- Ключевое требование краткости в длинном system prompt продублировать коротким
  `<tone_preference>` ближе к концу.

## Шаг 3 — Симптом → рычаг (ядро)

Открыть reference своей модели и взять ДОСЛОВНО те блоки, чей симптом реально относится к задаче.
**Opus 5.5 / Sonnet 5.5 / Haiku 5.5** — оглавление `references/models-5-5-blocks.md` (unattended,
напоминание «user hasn't heard from you», сигналы времени `elapsed 340s / 1200s`, «explore broadly»,
`<pasted_content>`, фронтенд-запреты, проверка кода, дата для поиска). Блоки Fable на других
моделях Anthropic не измеряла: брать их туда только при том же симптоме и проверять на своих
задачах. **Fable 5.1** — индекс
`references/fable-5-1-blocks.md`:

| Симптом / потребность | § | Куда вставляется |
|---|---|---|
| Не выбран уровень effort; латентность и цена выше, чем задача того стоит | 1 | `[harness]` |
| Между вызовами инструментов почти нет текста; агент «молчит» минутами | 2 | `[harness]` + system |
| Один вызов инструмента за ход в кодинг/computer-use цикле | 3 | turn-scoped system после tool_result |
| `bound to a different conversation`; обвязка правит ранние ходы | 4 | `[harness]` |
| Проза плотная, длинные предложения, мало абзацев | 5 | user (предпочтительно) или system |
| Ответы в чате менее структурированы, чем требует содержание | 6 | СНЯТЬ старые анти-форматные правила, затем system |
| В пересказе источник воспроизводится без пометки цитаты | 7 | пример в system + подставить имя своего инструмента |
| Ход кончается раньше работы; спрашивает разрешение на уже заказанное | 8 | system, оба блока |
| Клиентская компакция теряет ограничения, решения, точные детали | 9 | инструкция суммаризатору |
| Незапрошенные фиксы и расширения; лишние коммиченные тесты | 10 | system |
| На `low` отвечает по памяти вместо поиска | 11 | поднять effort на ход либо system |
| Безобидные кодинг-запросы дают `stop_reason: "refusal"` | 12 | переформулировать запрос / контекст языка / убрать base64 |
| Файл переписывается целиком ради мелкой правки | 13 | конец system или первого user |
| На `xhigh`/`max` долго и упирается в `max_tokens` | 14 | конец user + `max_tokens` в обвязке |
| Ведущий агент простаивает, пока работают субагенты | 15 | `[harness]` |
| Ответы по графикам и плотным изображениям теряют детали | 16 | `[harness]`: контейнер или crop-инструмент |

**Сначала снять, потом добавлять.** Классы строк из эпохи прежних моделей, которые на новых
работают ПРОТИВ цели — искать их в существующем промпте прежде, чем что-то дописывать:

1. Глушилки нарратива («hold all findings for the final response») — при жалобе на тишину агента.
2. Анти-форматные правила («не используй буллеты/болд/заголовки») — Fable 5.1 и так недоформатирует.
3. «Think carefully before answering» в чат-промптах Opus 5.5 — глубину задаёт effort, строка лишь
   задерживает ответ (`models-5-5-blocks.md`, B7).
4. Просьбы перепроверить работу — **по модели, а не всегда** (`models-5-5-blocks.md`, E):
   - снимать только расплывчатые повторные перепроверки, перенесённые из промптов Opus 5
     («double-check your answer», «re-verify before responding», «use a subagent to verify»), и
     только у Opus 5 (дают over-verification) — или у других моделей по наблюдаемому симптому;
   - Fable 5.1 / Opus 5.5 — по симптому; Sonnet 5.5 на `low` и Haiku 5.5 на `low`/`medium` —
     наоборот, ДОБАВИТЬ блок проверки (C7);
   - **не удалять никогда:** самопроверку против конкретных критериев («сверь кадры с эталоном,
     исправь 3 худшие»), запуск тестов, сборки, линтеров, скриптов-валидаторов и автопроверок
     рендера. Это не over-verification, а часть поставки: рендер без них — брак.
   Проверка ВНЕШНИХ фактов поиском — отдельный случай, на `low` она нужна (§11, D2).

## Шаг 4 — Анти-паттерны (чек-лист перед выдачей)

1. ❌ **Расплывчатые перепроверки из промптов Opus 5** («double-check your answer») на модели, где
   они дают over-verification, — удалять. Детерминированные проверки (тесты, сборка, валидаторы,
   автопроверки рендера) и самопроверку против критериев — оставлять (Шаг 3, п. 4).
2. ❌ **«Be conservative» / «only report high-severity» в ревью-промптах** — выполнится буквально,
   реальные находки замолчатся. Правильно: «report everything», фильтрация отдельным проходом.
3. ❌ **Агрессивный тон** («CRITICAL: You MUST…») — вызывает overtriggering инструментов; писать
   нормально («Use this tool when…»).
4. ❌ **Только запреты без позитивной альтернативы** — «не используй markdown» → «пиши плавной
   прозой цельными абзацами».
5. ❌ **Blanket-дефолты** («If in doubt, use [tool]», «Default to [tool]») → целевые условия
   («Use [tool] when it would enhance your understanding»).
6. ❌ **Упоминание `<thinking>`-тегов по имени** в запретах — увеличивает утечку; общая форма:
   «Do not include internal or system XML tags in your response».
7. ❌ **Расчёт на prefill** последнего assistant-хода — не поддерживается с 4.6+; вместо него
   structured outputs или прямые инструкции формата.
8. ❌ **Расплывчатое «сделай хорошо»** — для «above and beyond» просить явно («Include as many
   relevant features as possible. Go beyond the basics»).
9. ❌ **Примеры мимо реального use case** либо слишком однотипные (модель выучит случайный паттерн).
10. ❌ **Отключение thinking ради экономии** — лучше thinking on + низкий effort. Если thinking всё
    же off: разрешить «brief sentence before using a tool» (иначе tool-calls текстом) и общий запрет
    внутренних XML-тегов.
11. ❌ **Демпфер субагентов без симптома** («не делегируй, не проверяй себя субагентом») —
    зависит от модели. Fable 5.1: ставить только по наблюдаемому лишнему делегированию; проблема
    ведущего обратная — простой под субагентами, правится обвязкой (§15). Sonnet 5.5 на
    `xhigh`/`max` сам запускает ревьюеров — для него есть свой блок (`models-5-5-blocks.md`, C3).
12. ❌ **Промпт длиннее, чем требует задача.** Короткой задаче — короткий промпт (роль + задача +
    формат). Полный каркас из Шага 2 — для системных промптов продуктов и агентов.
13. ❌ **Просьба выписать рассуждения в ответ** («покажи ход мысли», «пиши рассуждения в
    `<thinking>`/в ответе») — на Opus 5.5, Sonnet 5.5, Fable 5.1 даёт отказ `reasoning_extraction`.
    Просить короткое обоснование или сводку действий; нужны рассуждения — `display: "summarized"`.
14. ❌ **«Не как ИИ» / «avoid a generic AI look»** для дизайна и моушна — меняет один дефолт на
    другой. Перечислять конкретные запрещённые приёмы (`models-5-5-blocks.md`, B9).

**Golden rule**: показать промпт «коллеге без контекста» — если запутается он, запутается и модель.

## Шаг 5 — Прочие поведенческие рычаги (вне гайдов по моделям)

Ставить по симптому, как и всё остальное:

- **Позиция к действию** — выбрать одну. Учитывать, что §8a (Fable) и B3 (Opus 5.5) уже задают
  автономность: с ними `default_to_action` не ставить.

```text
<default_to_action>
By default, implement changes rather than only suggesting them. If the user's intent is unclear,
infer the most useful likely action and proceed, using tools to discover missing details instead
of guessing.
</default_to_action>
```

```text
<do_not_act_before_instructions>
Do not jump into implementation or change files unless clearly instructed. When intent is
ambiguous, default to research and recommendations rather than taking action.
</do_not_act_before_instructions>
```

- **Анти-галлюцинации в коде**:

```text
<investigate_before_answering>
Never speculate about code you have not opened. If the user references a specific file, read it
before answering. Give grounded answers based on investigated code.
</investigate_before_answering>
```

- **Анти-подгонка под тесты**: «general-purpose solution; tests verify correctness, not define the
  solution; if a test is wrong — report it, don't work around it».
- **Обратимость действий** (автономный агент): локальные обратимые — свободно; деструктивные и
  публичные (force-push, удаление, посты вовне) — спрашивать; не обходить защитные проверки
  (`--no-verify`) как «шорткат».
- **Long-horizon**: state в структурированных файлах (`tests.json` + freeform `progress.txt`), git
  как журнал и чекпоинты, инкрементальный прогресс, явный bootstrap для нового контекстного окна
  («Review progress.txt, tests.json, and the git logs»), инструменты самопроверки, «не
  останавливайся раньше времени из-за токен-бюджета — сохрани состояние и продолжай».

## Шаг 6 — Формат выдачи пользователю

1. **Готовый промпт** в fenced-блоке; при разделении — отдельно `SYSTEM` и `USER`; переменные —
   `{{PLACEHOLDER}}`.
2. **Обоснование** — 3–6 пунктов: какой рычаг применён и против какого симптома задачи (не пересказ
   теории). Для взятых из библиотеки — ссылка на номер §.
3. **Изменения в обвязке** — отдельным списком, если среди рычагов есть `[harness]`: beta-заголовки,
   `thinking.display`, turn-scoped system messages, `max_tokens`, поведение субагентов. Их нельзя
   выдать текстом промпта, и молчать о них нельзя. **Claude Code:** субагент не видит разговор, но
   читает CLAUDE.md (кроме Explore, Plan и агентов с `omitClaudeMd: true`) — правило, которое ему
   нужно, повтори в задании; ограничения задавай полями `tools`, `maxTurns`, `effort`, `model`, а
   не только текстом (`video-templates.md`, раздел 5).
4. **Допущения и ручки тюнинга** — что предположил и что подкрутить, если поведение не то
   («многословит → §5 mannered prose»; «тишина в цепочке → сперва `display: "updates"`, потом §2»).
5. **Язык промпта**: по умолчанию английский (максимальная управляемость), user-facing строки
   продукта и примеры — на языке продукта. Просят промпт целиком по-русски — писать по-русски, но
   предупредить, что блоки библиотеки измерены в англоязычном оригинале.
6. **Effort** — рекомендация по Шагу 0.4, если целевая платформа его поддерживает.

## Шаг 7 — Ревизия существующего промпта (миграция на новую модель)

Когда на вход дали готовый промпт, а не задачу:

1. Прогнать по списку «сначала снять» Шага 3 — это самая частая причина, что старый промпт на
   новой модели ведёт себя хуже, чем на прежней. Сбросить effort на дефолт новой модели и сделать sweep.
2. Прогнать чек-лист Шага 4.
3. Сопоставить жалобы пользователя с таблицей Шага 3 и добавить недостающие блоки дословно.
4. Выдать: правленый промпт целиком + список «убрано / добавлено / почему», не только дельту прозой.

  Поддерживает thinking off на `high` и ниже; на Opus 5.5 thinking выключить нельзя
  (`models-5-5-blocks.md`, B2).
- **Fable 5 → 5.1:** промпты переносятся без правок, sweep effort — заново (`fable-5-1-blocks.md`,
  «Старое»).
- Prefill последнего assistant-хода не поддерживается с поколения 4.6.
