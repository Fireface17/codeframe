## 1. Когда брать

- **Рубрика «Как устроено»**: вещь из руки зрителя с движущимися частями — замок, кнопочная ручка, кран,
  степлер, шарнир, редуктор. Петли (поворот, вращение, сдвиг), ведомые петли (одна часть тянет другую),
  разборка по деталям, разрез (`split`).
- Технические формы: корпуса, детали, мебель, механизмы, шестерни (`gear`), резьба (`thread`), рифление (`knurl`).
- **Не брать**: персонажи, животные, лица, ткань, природа, органика — sand3d их не умеет. Для них —
  Higgsfield (`generate_3d`) или рисунок. Город из кубиков и частицы — проще прямо в three.js (`3d.md`).
- 3D-рендер медленнее SVG примерно в 4 раза: в режиме «до 3 ч» — одна-две 3D-сцены, не весь ролик.

## 3. Как писать программу предмета

Перед первой строкой прочитай `api.md` целиком и `guidelines.md` — без них будут ошибки в осях и петлях.
Файл программы клади рядом со сценой: `lab/ideas/<slug>/model/<имя>.py` или `projects/<nn>/models/<имя>.py`.

Форма программы (правила из `guidelines.md`, на них держится весь образец):

```python
import sand3d as s3d                       # и больше ничего на уровне модуля


def padlock(w=40, d=18, h=34, gap=22, lift=10, key_h=0.38, key_in=10):   # ГОЛОВА: первая функция, оглавление
    body = body_part(w, d, h)

    f = s3d.local(body, -gap / 2, 0, h)                   # ОДИН кадр на петлю: и для at, и для joint
    shackle = s3d.at(shackle_part(gap), on=f)
    s3d.seat(body, shackle)                               # вырезать в корпусе место под деталь, как она стоит в покое

    fk = body.face("-Y").move(0, h * key_h)               # кадр на грани; Z кадра — наружу
    key = s3d.at(key_part(), on=fk.offset(-key_in))
    s3d.seat(body, key)                                   # скважина по форме ключа

    s3d.joint("key_turn", key, fk, axis="normal", range=(0, 90))
    s3d.joint("lift", shackle, f, kind="prismatic", axis="+Z", follows="key_turn", ratio=lift / 90)  # ведомая
    s3d.joint("swing", shackle, f, axis="+Z", range=(0, 180))
    return s3d.assembly("padlock", body, shackle, key)


def body_part(w, d, h, r=5):                              # ДЕТАЛЬ: своя функция, строится в своём начале координат
    body = s3d.box("body", w, d, h)
    s3d.fillet(body, r, edges="side")
    s3d.material(body, "brass", color="#c9a24a")
    return body
```

- Миллиметры, Z вверх, **лицо предмета смотрит -Y** (слова `front`/`back` в `anchor` — это -Y/+Y).
- Каждый размер назван один раз в сигнатуре, остальное выводится из него. Ориентир — 15 чисел на деталь.
- Повторы — `on=s3d.grid(...)`, `ring`, `along`; пара — `s3d.transform(s3d.copy(x), mirror="x")`. Без циклов с sin/cos.
- Всё строится в покое (петли в 0), `s3d.pose` в программе не пишем — позы ставит сцена.
- Петля: деталь сначала ставится (`at`), потом `joint` говорит, как она движется. Знак оси решает,
  куда откроется: положительное значение — поворот по правилу правой руки. Не туда — поменяй знак оси.
- Ведомая петля: `follows="<петля>", ratio=…` (мм на градус или градусы на мм) — в ролике её не крутим, она идёт сама.
- Цвет: `s3d.material(ob, "<вид>", color="#rrggbb")` один раз, до повторов. Виды: oak walnut pine birch steel
  brushed_steel chrome aluminium brass copper painted_metal plastic glossy_plastic rubber glass ceramic fabric
  velvet leather marble concrete light. `join` — один материал (первого), `group` — каждому свой.
- `bpy` и `bmesh` в программе запрещены: чего нет в словаре — того sand3d не умеет.

## 4. Сборка

```bash
tools/sand3d/run <программа.py> --png [--pose key_turn=90,swing=150] [--view 35,22] [--out папка]
```

| Флаг | Что |
|---|---|
| `--fn имя` | головная функция, если она не первая в файле |
| `--png` | превью Cycles 900×900, светлый фон; смотри его глазами (Read) после каждой правки |
| `--pose петля=знач,…` | поза для превью: градусы или мм программы (GLB всё равно пишется в покое) |
| `--view az,el` | ракурс превью в градусах; `0,0` — строго спереди (-Y), по умолчанию `35,22` |
| `--stl`, `--urdf` | заодно STL (печать, Z вверх) или URDF (симуляторы) |

Рядом с программой появятся: `<имя>.glb` (метры, Y вверх, петли — в `extras.s3d_joint` узлов),
`<имя>.glb.js` (тот же GLB в base64 → `window.GLB_DATA["<имя>"]`, для страницы с `file://`; генерируется —
руками не править), `<имя>.json` (детали, петли с пределами, габарит в мм, время), `<имя>.png`.

Время: ~16 с запуск Blender + 0,1–0,5 с сборка + ~2 с превью. Ошибка — код 1 и одна строка
`ОШИБКА <тип>: <текст>` + строка программы, где упало; текст ошибок sand3d говорит, что исправить.

Цикл работы: написать → `run --png` → посмотреть PNG (и с открытой позой `--pose`) → поправить → повторить.
Две-три итерации на предмет — норма.

## 5. Предмет в ролике

**Подключение.** Лаборатория: в `meta.json` идеи
`"scripts": ["js/vendor/three.js", "js/gl.js", "js/glb.js", "ideas/<slug>/model/<имя>.glb.js"]`
(three.js 0.170.0 и `gl.js` в `lab/` уже есть). Проект: `new_project.sh … --3d` (ставит three, `gl.js`,
`glb.js`), потом в `index.html` перед `js/film.js` — `<script src="models/<имя>.glb.js"></script>`.

**API `glb.js`:**

```js
GL.scene('padlock', ({ THREE, R, W, H }) => {
  R.toneMapping = THREE.ACESFilmicToneMapping;
  const scene = new THREE.Scene();
  scene.environment = GLB.studio(THREE, R);          // металлу нужно окружение, иначе латунь и хром чёрные
  const key = new THREE.DirectionalLight(0xfff4e6, 1.6); key.position.set(-1, 2, 1.5); scene.add(key);

  const M = GLB.load(THREE, 'padlock');              // синхронно, из window.GLB_DATA
  // кадрируем по ВСЕМУ движению: открытая поза ∪ покой, потом вернуть покой
  M.set('key_turn', GLB.deg(90)); M.set('swing', GLB.deg(150)); M.root.updateMatrixWorld(true);
  const box = M.box.clone().union(new THREE.Box3().setFromObject(M.root)); M.pose();
  M.root.position.sub(box.getCenter(new THREE.Vector3()));
  scene.add(M.root);
  const cam = new THREE.PerspectiveCamera(28, W / H, 0.001, 10);
  /* дистанция по ширине кадра: r / sin(hfov/2), hfov = 2·atan(tan(vfov/2)·W/H) */
  return (lt, p) => {
    M.set('key_turn', p.key);                        // радианы; ведомая lift идёт сама
    M.set('swing', p.swing);
    /* камера из lt */
    return { scene, camera: cam, clear: '#ece8e1' };
  };
});
// в frame(t):
const kDeg = 90 * (prog(t, T.key, 0.8, ease.inOut) - prog(t, T.unkey, 0.8, ease.inOut));
GL.draw('padlock', t - T.s1, { key: GLB.deg(kDeg), swing: … });
```

- `M.set(имя, значение)` — радианы (revolute/continuous) или **метры** (prismatic); ставит из покоя,
  состояния не копит — можно звать в любом порядке, кадр остаётся функцией t.
- `M.joints` — петли с `type`, `lower`/`upper` (рад или м), `mimic`; `M.nodes[имя]` — любой узел;
  `M.parts` — узлы с сетками; `M.box` — габарит в покое (метры).
- Единицы GLB — метры: замок 4 см. Камеру ставь от габарита, не числами «на глаз».
- Подписи и цифры — в SVG поверх (`#root > svg` над холстом); значения бери из тех же чисел, что крутят модель.
- `GLB` и `GL` — глобальные; в `core.js` уже есть функция `pose` — свои переменные так не называй.

## 6. Разборка по деталям

Для «из чего состоит»: при построении запомни покой каждой детали, в кадре ставь `покой + сдвиг` (чистая
функция t, без накопления):

```js
const center = M.box.getCenter(new THREE.Vector3());          // до сдвига M.root
const rest = M.parts.map(({ node }) => ({ node, p: node.position.clone(),
  dir: node.getWorldPosition(new THREE.Vector3()).sub(center).normalize() }));
// в draw: for (const r of rest) r.node.position.copy(r.p).addScaledVector(r.dir, k * 0.02);  // k: 0..1
```

Сдвиг направления лучше задать руками по деталям (вверх, вбок), а не «от центра» — так читается порядок сборки.
Узлы деталей с петлями вложены в узлы петель: двигай узел детали, а не узел петли (его ставит `M.set`).

## 7. Детерминизм и скорость

- Программа sand3d детерминирована побайтно; `glb.js` строит сцену синхронно — кадры двух прогонов
  совпадают побайтно (проверено `render.mjs still` дважды + `cmp`).
- Образец 1080×1920: лист из 8 кадров — 2 с; черновик 5,6 с (`SUB=4`, 6 воркеров) — 55 с; полный рендер
  (16 подкадров) — по оценке ×4, около 4 мин (не мерили).
- Модели лёгкие: замок 45 КБ, стиральная машина 94 КБ, ~800 граней.

## 8. Грабли (найдены на пробе)

- **Оси кадра грани.** На вертикальной грани X кадра — вдоль грани, Y — вверх, Z — наружу. Деталь, построенная
  по своему Z (лезвие ключа), выходит из грани. Ширина и толщина детали — по X и Y этого кадра: ключ
  `box(2, 7, 24)` стоит вертикально, `box(7, 2, 24)` лежит плашмя. Проверяй на PNG.
- **Вырезы под детали — `seat(host, part)`**, а не ручные `hole`/`pocket`: вырежет ровно по форме, в покое.
- **Металл без окружения чёрный** в three.js — `GLB.studio(THREE, R)`. В превью Blender этого нет.
- **Кадрирование по покою режет движение**: открытая дужка уходит за край. Габарит — по крайним позам.
- **Превью Blender ≠ кадр three.js** (другой свет и тоны): цвет и свет сверяй по листу `render.mjs sheet`.
- **Одна программа — один процесс**: `run` каждый раз начинает с пустой сцены; не собирай два предмета в одном файле.
- Открытые ошибки 1.6.3: имя тела от 52 символов → KeyError; пересечение непересекающихся тел даёт пустую
  сетку без ошибки. Имена держи короткими.

## 9. Чего не умеет и о чём помнить

- Только твёрдые формы из словаря; свободные поверхности — через `loft`/`station`/`body`, грубо.
- Текстур нет: материал = цвет + шероховатость/металл. Дерево и мрамор в GLB — просто цвет.
- STL для печати не проверяется на толщину стенок и замкнутость.
- Стиль: глянцевый 3D-предмет на градиенте — примета ИИ-роликов (`unslop-video`, раздел 3D). Свет, фон
  и материал решай в паспорте ролика (`unique.md`); по умолчанию — светлый фон, один ключевой свет, матовость.
- Лицензия sand3d — Apache-2.0: библиотеку и примеры можно использовать.
