## 1. Устройство страницы

`index.html` подключает по порядку: `vendor/rough.js` → `timing.js` (WORDS, WAVE) →
`code-data.js` → `core.js` → `code.js` → `captions.js` → `cast.js` → `film.js` → `preview.js`.
Классические скрипты, не ES-модули: модули не грузятся с `file://` (CORS), а рендер
открывает страницу именно так (обход с importmap и флагом Chrome есть, но ломает превью по
двойному клику — `references/3d.md`). С `--3d` между `cast.js` и `film.js` встают
`vendor/three.js` и `gl.js`.

`film.js` обязан выставить:
```js
window.DURATION = Math.round(T.end * FPS) / FPS;   // кратно кадру
window.T = T;                                      // cue-таблица (node render.mjs cues)
window.SFX_EVENTS = SFX;                           // звуки для сведения
window.CUTS = [T.s2, T.s3];                        // склейки (необязательно): mix.py проверит хвосты звуков
window.SUBMAP_AUTO = [[t0, t1, 40]];               // (необязательно) больше подкадров на быстрых участках
window.SAFE = { x0, x1, y0, y1, xLow?, yLow?, skipAfter? };   // безопасная зона для проверки
window.seek = t => frame(clamp(t, 0, DURATION));
window.READY = (async () => { await loadFonts(); await preloadImages(svg); /* build captions */ frame(0); return true; })();
```
Не называй внутреннюю функцию `seek`: `window.seek = t => seek(t)` рекурсивно вызовет само
себя (глобальная функция и есть `window.seek`). Используй `frame`.

Структура `film.js`: палитра и раскладка → cues `T` (от слов) → построение сцены один раз →
`frame(t)`, который только выставляет атрибуты.

## 2. Время и пружины (`core.js`)

```js
step(t, sp)            // 0 -> 1, отклик затухающей пружины; 0 при t <= 0; sp = { r, z }
after(t, t0, sp)       // step(t - t0, sp)
vis(t, tin, tout, si, so)            // вход пружиной si, выход so
track(v0, [[t, v, sp?], ...], def)   // значение, цель которого меняется много раз
prog(t, t0, d, ease.inOut)           // 0..1 за [t0, t0 + d], ровно 0 до и 1 после
popS(t, t0) / popO(t, t0)            // масштаб 0.35 -> 1 с перелётом / быстрая непрозрачность
squash(s, k)           // { sx: s(1+k), sy: s(1-k) }: k > 0 сплющить, k < 0 вытянуть, объём сохраняется
hash01(i, seed)        // детерминированная «случайность»
```
`r` — период незатухающих колебаний (с), `z` — коэффициент затухания. Пресеты `SP` и
смысл чисел — `references/motion-language.md`. Пружина никогда не приходит ровно в 1:
где нужен точный финал (последний кадр петли), бери `prog` с easing.

`track` суммирует пружины по каждой смене цели: события сортируются по времени. Если на
реальном голосе два cue поменялись местами, результат неожиданный — упрости события.

## 3. SVG и позы

```js
S(tag, attrs, parent)          // создать элемент
A(el, attr, value)             // кэшированная запись: DOM трогается только при изменении
setText(el, s)                 // то же для textContent
show(el, o)                    // opacity + visibility
place(g, x, y, s, o)           // перенос + равномерный масштаб вокруг локального начала
pose(g, x, y, sx, sy, rot, o)  // + анизотропный масштаб и поворот (градусы)
popAt(g, cx, cy, s, o, dy)     // масштаб вокруг точки в координатах родителя + подъём
rise(el, a, dy)                // проявление текста с подъёмом
mixPose(a, b, m)               // смешать позы {x, y, sx, sy, rot}
```
Строй элементы в локальных единицах (блок 100×100 с центром в начале), а масштаб давай
позой: так одна и та же фигура работает в любой сцене и формате.

**Ловушка видимости SVG:** `visibility="visible"` у потомка перебивает `hidden` у родителя.
Целые сцены переключай через `display` (`A(scene, 'display', on ? 'inline' : 'none')`).

## 4. Линии

```js
drawStroke(parent, d, attrs)   // .draw(v): путь рисуется от 0 до v (pathLength=1 + dashoffset)
drawDashed(parent, rrHalves(x, y, w, h, r), attrs)   // пунктир, который проявляется маской
roughD(d, { seed, roughness, disableMultiStroke })    // рукописный контур rough.js
roughPath(parent, d, seed, width, attrs)
rr(x, y, w, h, r), rrHalves(...)   // скруглённый прямоугольник / две половины от центра верха
handLoop(r, turns, seed)           // «обвод маркером» с перехлёстом
```
- Пунктир нельзя рисовать сдвигом `dashoffset` — штрихи поползут. `drawDashed` держит
  штрихи на месте и проявляет их маской.
- У rough.js по умолчанию двойной штрих: для рисующихся линий ставь `disableMultiStroke`,
  иначе линия «нарисуется дважды подряд».
- Seed фиксированный: иначе контуры «кипят» от кадра к кадру. Если нужен эффект живой линии,
  меняй seed ступенькой раз в 4–6 кадров, а не каждый кадр.
- `rrHalves` рисует рамку симметрично от центра верха вниз по обеим сторонам — выглядит
  аккуратнее, чем обход по кругу.

## 5. Cues от слов

```js
word('пружина')       // { w, start, end, i } первого вхождения
word('и', 2)          // второе «и» — короткие слова повторяются, считай вхождения!
phrase(3)             // { i, start, end, text } третьей фразы
pw(3, 'кадр')         // слово, начинающееся с «кадр», только внутри фразы 3 (+ номер вхождения: pw(3, 'и', 2))
```
`pw` надёжнее `word`, когда такое же слово уже звучало раньше: поиск ограничен границами фразы,
совпадение по началу слова («функци» найдёт «функция»).
Пример таблицы cues:
```js
T.s2 = phrase(2).start - 0.1;            // сцена начинается чуть раньше фразы
T.hl = word('пружина').start - 0.08;     // акцент на 60–100 мс раньше слова
T.end = window.WORDS.duration + 0.35;
```
Ошибка из практики: `word('И')` нашёл «и» из третьей фразы вместо шестой, и отъезд камеры
сработал не там. Для односложных слов всегда указывай номер вхождения.

## 6. Субтитры (`captions.js`)

```js
const caps = makeCaptions(layer, spec, { x, y, size, lh, maxW, anchor, valign, end });
caps.frame(t);
spec = [{ lines: [[['Это', 0], ['не', 1]], [['After', 2, 's'], ['Effects.', 3, 's']]], scale: 1.25 }, ...]
autoCaptions({ maxWords: 3, maxChars: 16 })   // запасной вариант из слов
```
Стили токена: `g b y p v` — маркер, `r` — красный текст, `s` — зачёркивание (рисуется),
`m` — моноширинная плашка кода, `c` — рукописный шрифт, `t` — тик со временем слова.
`valign: 'bottom'` — многострочная фраза растёт вверх (для горизонтали у нижнего края).
`anchor: 'middle'` — центровка. Строй субтитры после `loadFonts()`: они измеряют текст.

## 7. Плашки кода (`code.js` + `tools/tokens.mjs`)

Файлы в `snippets/` → `node tools/tokens.mjs` → `window.CODE_DATA[имя]` (токены Shiki).
```js
const sc = codeScene(group, { from: CD.step, x0, y0, size: 40,
  type: { t0, t1, seed },          // печать по символам с «человеческим» ритмом и кареткой
  hl: [{ line, t0, t1 }], dim: 0.35,   // подсветка строки, остальные гаснут
  zoom: { t0, t1, s, line },       // наезд на строку
  to: CD.next, morph: { t0, dur } });  // морф токенов в другую версию кода
sc.seek(t)            // или sc.eval(t); подменить e.stx; sc.apply()
```
- **Морф токенов** хорош, когда две версии родственные (переименование, новая строка).
  Между несвязанными сниппетами он превращается в кашу: используй «уход вверх + печать»
  (старая плашка уезжает за 0,2 с, новая печатается).
- **Живые числа:** найди элементы `sc.els.filter(e => e.t === '0.84')`, после `eval`
  замени `e.stx` текущим значением (только если токен уже допечатан: `e.stx === e.t`),
  потом `apply`. Так `t = 1.20` или `dashoffset = 0.37` меняются синхронно с картинкой.
- Читаемость на телефоне: 36–44 px, строка ≤ 28 символов, если плашка ниже y=840 в
  вертикали (справа кнопки TikTok). Темы: `github-dark-high-contrast`, `houston`.
- Шрифт JetBrains Mono (npm `jetbrains-mono`): кириллица и стрелки есть, моноширинность
  0,6 em — позиция токена = колонка × 0,6 × кегль.

## 8. Персонажи (`cast.js`)

```js
const hero = makeShape(stage, 'blob', { fill: '#fceda3', seed: 21 });  // колобок с лицом
makeShape(parent, 'star'|'square'|'tri'|'heart'|'circle', { fill, seed, xray })
A(hero.eyes, 'transform', blinkT(t, [1.1, 3.0, 5.2]));   // моргание в заданные моменты
jumpPose(tau, { x0, x1, y, s, height, flip })             // присед → дуга (+сальто) → сквош
```
`xray: true` — «чертёж»-двойник (контур, перекрестие, рамка, подпись координат) для сцен
«как это устроено». Своих персонажей делай так же: путь ~100 единиц, центр в начале.

## 9. Паттерны сцен

- **Смешивание поз между сценами.** Поза героя — функция времени для каждой сцены; сцены
  подмешиваются по очереди:
  ```js
  let p = shot1(t);
  if (t > T.s2) p = mixPose(p, shot2(t), after(t, T.s2, SP.move));
  if (t > T.s3) p = mixPose(p, shot3(t), after(t, T.s3, SP.move));
  ```
  В момент начала сцены вес 0, поэтому поза никогда не прыгает.
- **Рентген / раскрытие сканом.** Две копии сцены (обычная и чертёж), `clipPath` с
  прямоугольником по линии скана: обычная видна ниже линии, чертёж выше.
- **Зум камеры в окно и обратно (петля).** Экран масштабируется вокруг неподвижной точки
  `F = pane / (1 − s)`: при s=1 трансформация тождественная, при s=pane.s экран встаёт в
  панель. Масштаб интерполируй логарифмически (`exp(lerp(ln 1, ln s, e))`) — так зум
  равномерен на глаз. Окно-рамку проявляй только в конце отъезда и гаси в начале наезда:
  пока оно огромное, оно ложится под субтитры.
- **Перемотка времени в кадре.** Демо-клип — функция своего локального времени `tau`;
  бегунок задаётся `track()`, а клип и число в коде берут один и тот же `tau`.
- **Мячик по словам.** Позиция x = момент слова на волне; между словами парабола, на
  приземлении сквош `k = 0.16 · exp(−Δt / 0.07)`.
- **Петля.** Первый и последний кадр одинаковы (обычно пустой фон): всё уходит за 0,3 с до
  конца, субтитр финала держится до самого конца (`end`), музыка режется целыми тактами.
- **Таблица сцен** `SCN = [{ k, t0, g, draw }]`, `t1` — `t0` следующей. В `frame(t)` ровно одна сцена
  `display: inline`, остальные `none`. Прятать сцену прозрачностью или `visibility` родителя нельзя:
  потомок с `visibility="visible"` остаётся виден, и элементы прошлых сцен просвечивали. В `READY` каждую
  сцену строй так: `inline` → построение (замер текста) → `none`. `window.CUTS = SCN.map(s => s.t0)`.
- **Переход в склейку считай от склейки назад:** `prog(t, tCut − d, d, ease.in4)`, где
  `tCut = SCN[k + 1].t0`. Пролёт, привязанный к слову, кончался на 0,5 с раньше склейки, и кадр «висел».
- **Первый кадр сцены не пустой:** на склейке уже виден главный элемент (заголовок или герой), остальное
  появляется по словам. Проверка — лист из кадров `t0 + 1/FPS` каждой сцены. Кадр 0 ролика — середина
  действия, а не статичная «обложка»: независимые оценщики раз за разом снижали балл именно за это.
- **Слой поверх (HUD, рамки, номер сцены):** цвет — по локальному фону каждой области; на разделённом
  экране у левой и правой половины свой. Таймкод — `mm:ss:ff` (минуты, секунды, кадры), не `00:00:ss`:
  тот ломается после 60 с.

## 10. Правила детерминизма

- Никаких `Math.random`, `Date.now`, `performance.now` в кадре; CSS-анимаций и transition
  нет; «случайность» — `hash01`.
- Шрифты: `loadFonts()` грузит **все** объявленные начертания. `document.fonts.load('40px X')`
  без текста не грузит кириллический поднабор — первые кадры выходили без кириллицы.
- Картинки: `preloadImages(svg)` до первого кадра.
- Масштабированный вложенный контент без флага `--disable-partial-raster` давал пиксели,
  зависящие от предыдущего кадра; флаг включён в `render.mjs`.
- Всё, что меняется, пиши через `A()` / `setText()`: это кэш и задел для пропуска
  неизменных подкадров.
- Камера с плавным зумом: масштаб в `transform` — 6 знаков после запятой. С тремя знаками
  медленный наезд идёт «ступеньками».

## 11. Производительность

- Подкадр 1080×1920 стоит ~8–14 мс; упор в CPU (Chromium + ffmpeg), 6 воркеров —
  практический потолок, больше не быстрее.
- `display: none` для неактивных сцен; `visibility: hidden` для мелочей.
- Тяжёлые фильтры (blur, drop-shadow) в SVG дороги на каждом подкадре: имитируй тень
  смещённой подложкой.

## 12. 3D-слой

Необязательный слой three.js (WebGL) под SVG: `new_project.sh --3d`, API `GL.scene / GL.draw / GL.clear`
в `js/gl.js`. Подключение для `file://` (пин `three@0.170.0`), холст под SVG и прозрачный фон SVG в
3D-сценах, `preserveDrawingBuffer`, время шейдера от начала сцены, мягкий максимум для морфов,
детерминизм и рендер — `references/3d.md`.
