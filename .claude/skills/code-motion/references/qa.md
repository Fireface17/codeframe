# Проверки качества

Содержание: 1. Ворота перед сдачей · 2. Контактные листы · 3. Автопроверки · 4. Свежий
рецензент · 4а. Независимый оценщик и «как на телефоне» · 5. Каталог дефектов · 6. Что проверяет человек

## 1. Ворота перед сдачей

| # | Проверка | Как | Порог |
|---|---|---|---|
| 1 | Число кадров | `render.mjs video` (сам), `ffprobe` | ровно N/N |
| 2 | Нет NaN и ошибок консоли | `render.mjs cues` выводит ошибки страницы | 0 |
| 3 | Безопасная зона | `node tools/safecheck.mjs 0.05` | весь читаемый текст внутри |
| 4 | Рывки | `uv run --script tools/jumps.py master.mp4` | флаги только на запланированных склейках |
| 5 | Шов петли (если петля) | `uv run --script tools/loopcheck.py master.mp4` | `OK: seamless` |
| 6 | Громкость | `mix.py` пишет LUFS/TP; `ffmpeg -af ebur128=peak=true` | −14 соцсети / −16 explainer, TP ≤ −1 |
| 7 | Сверка с макетами | `node tools/refcheck.mjs` | расхождение — единицы пикселей |
| 8 | Читаемость | лист середин переходов + правило 0,3 с/слово | ни одного «каши» |
| 9 | Рецензент | субагент по кадрам готового MP4 | реальные дефекты исправлены |
| 10 | Конфиденциальность | поиск по исходникам и тексту в кадре | нет материалов заказчика в публичном |

## 2. Контактные листы

- Во время работы: `node render.mjs sheet out/sheet.png <времена> <колонки>` — по 2–3 кадра на
  сцену и **середины переходов** (именно там живут двойные экспозиции и столкновения).
- После правки таймингов — лист на реальном голосе: начало каждой фразы, ключевые слова.
- Из готового MP4 (а не со страницы): кадр каждые 0,5 с в сетку — так видно то, что видит
  зритель, включая motion blur. Кадры берутся по точным номерам, подпись — точное время кадра
  (фильтр `fps=2` сдвигает кадры на ~0,25 с, и критик ищет дефект не там):
  ```bash
  uv run --script tools/contact.py out/final/film_v1.mp4 out/review/sheet.png --step 0.5 --cols 10 --w 216
  ```
- Крупные кадры ключевых моментов (4 в ряд) — для оценки дизайна.

## 3. Автопроверки

- `safecheck.mjs` проходит ролик с шагом 0,05 с и сообщает каждый текст, вышедший за
  `window.SAFE`, с временем. Ловит мгновенные выходы во время въезда (подпись шкалы на 30 px
  ниже на въезде — уже под кнопками TikTok). Декоративный текст помечай `data-texture`.
- `jumps.py` считает изменение картинки между кадрами и сравнивает с окрестностью. Флаг на
  смене субтитров — повод проверить исчезновение (должно идти 0,1 с, а не мгновенно).
  Плавные большие изменения (наезд камеры) — не рывки.
- `loopcheck.py` сравнивает последний кадр с первым: разница должна быть на уровне обычной
  разницы соседних кадров.

## 4. Свежий рецензент

Субагент, который не видел кода и разговора. Лимиты проходов (~30 мин, 2–3 параллельно по диапазонам сцен,
≤12 кадров, ≤2 итераций) — `references/process.md` §3. Промпт (заполни скобки):

```
Ты свежий рецензент-моушн-дизайнер. Кода ты не видел и видеть не должен. Оцени готовый
ролик ({формат}, {длительность}, {площадки}) как зритель и арт-директор. Только чтение.
Задумка: {2–4 предложения: о чём ролик, сцены по порядку, голос, субтитры}.
Материалы: контактный лист из готового MP4 (кадры каждые 0,5 с): {путь}; кадры: {папка};
видео: {путь} (ffmpeg -ss <t> ... для любых моментов; особенно середины переходов: {времена}).
Тест молчаливого зрителя: понятна ли мысль по картинкам и субтитрам?
Найди: нечитаемый/мелкий текст; текст, исчезающий раньше, чем его прочтёшь; столкновения;
грязные кадры в переходах (двойная экспозиция); пустые или скучные кадры; непонятные места;
шаблонность; слабый хук в первые 1,5 с.
Отчёт до 400 слов: 3 сильные стороны; до 8 проблем по убыванию: время → что не так →
конкретное исправление; вердикт: готово или нет. Без вкусовщины — реальные дефекты.
```
Оценивай замечания по существу: часть может противоречить требованиям платформы
(«пустая нижняя треть» — это зона интерфейса в вертикали). Не соглашайся автоматически,
объясни пользователю, что принял и что нет.

## 4а. Независимый оценщик и проверка «как на телефоне»

**Независимый оценщик** — после внутренних проверок, по сценарию до производства и по ролику перед сдачей:
один субагент сильной модели, сначала 3–5 мин свежих гайдов по своей сфере, видит только работу и гайды
(отчёты критиков, прошлые оценки и документ сценария закрыты). Проход ≤10 мин, отчёт ≤20 строк: оценки 0–10,
3 сильных, 3 слабых, одна главная правка, прогноз. Итог ниже 8 — правим до публикации. Подробно и почему —
`references/process.md` §7.

**Проверка «как на телефоне»:**
- кадры уменьшить до 360 px по ширине (так ролик видят в ленте), обложку — до 130 px (сетка профиля):
  читается ли главное слово, понятен ли предмет;
- средняя яркость против эталона: `ffmpeg -i final.mp4 -vf signalstats,metadata=print:key=lavfi.signalstats.YAVG -f null -`.
  Стилизованные сцены выходили вдвое темнее эталона — на телефоне это «грязный» ролик;
- первый кадр (t = 0) — середина действия, не пустой фон и не статичная обложка: оценщики снижают
  балл именно за это;
- лист из кадров `t0 + 1/FPS` каждой сцены: на склейке уже виден главный элемент.

## 5. Каталог дефектов (встречены на практике)

| Дефект | Как проявился | Исправление |
|---|---|---|
| Двойная экспозиция субтитров | на смене фраз два текста слились в «Лини мрисуется» | старое уходит за 0,1 с и полностью до начала нового (30 мс зазор) |
| Финальная фраза гаснет | главная мысль читалась 0,5 с в блёклом виде | последний субтитр держится до конца ролика |
| Тёмное окно под субтитром | при зуме огромная тёмная рамка легла под чёрный текст | рамку проявлять в конце отъезда и гасить в начале наезда |
| Слабый хук | первый кадр почти пустой, заголовок мелкий и серый | каскад с первого кадра, хук ×1,25, яркость непроизнесённых слов ~0,46 |
| Неразборчивые непроизнесённые слова | opacity 0,28 (контраст 1,3:1) | 0,46 (~3:1) |
| Подпись отстаёт от слова | рукописное имя дописывалось после того, как его произнесли | ускорить и начать на 0,16 с раньше слова |
| Морф кода в кашу | токены несвязанных сниппетов разлетались | уход вверх + печать |
| Живое число застряло | заменённый токен в морфе был «swap» | без морфа, или подмена в обоих текстах swap |
| Зачёркивание видно 0,1 с | рисовалось после конца слова, а фраза сменялась | начинать с началом зачёркиваемого слова |
| Последовательность не успела | третья стрелка не дорисовалась до склейки на реальном голосе | сжать шаги, чтобы всё кончилось с фразой |
| Подписи налезли друг на друга | координаты в «рентгене» второго ряда легли на названия | убрать лишние подписи или развести по высоте |
| Текст под кнопками | подпись на въезде на мгновение ниже y=840 справа | въезд без смещения (только проявление) или подпись левее |
| Логотип перекрыл содержимое | статичный макет: логотип поверх переписки | логотип «уезжает» в шапку + вариант строго по макету |
| Нарушение комментария ТЗ | элементы сдвинуты, хотя «keep in place» | следовать дословно или согласовать отступление |
| Мыльные логотипы | вырезка 100 px из макета увеличена до 150 px | векторы; вырезки ×2 с лёгкой резкостью и предупреждение |
| Звуки «противные» | синтезированные пики на 14–23 дБ над музыкой | записанные мягкие сэмплы, на 6 дБ тише голоса |
| Звуки не совпадали | события на дробных долях, 3 звука за 0,1 с | события на долях/словах, не больше одного звука за 0,1 с |
| Курсор кликал на ходу | промах до 330 px | курсор останавливается на цели до клика |
| Раскладка прыгала | модалка и новые строки сдвигали всё мгновенно | плавное раздвигание |
| Противоречивые цифры | 512 против 187, у одного кандидата три разных балла | одна таблица фактов на весь ролик |
| Белая вспышка | резкий переход в новую сцену | растворение и подогнанный первый кадр |
| Текст обрезан краем | крупное слово выходило за кадр | проверка безопасной зоны |
| Тайминги «поплыли» | темп трека менялся 150→152 BPM | доли из анализа, не из сетки |
| Элементы прошлых сцен просвечивали | сцены прятались прозрачностью родителя, потомок с `visibility="visible"` остался | сцены переключать через `display` (engine.md §9) |
| Кадр «висел» перед склейкой | пролёт привязан к слову и кончился на 0,5 с раньше склейки | переход считать от склейки назад (engine.md §9) |
| Пустой первый кадр сцены | главный элемент появлялся по слову, через 0,3 с после склейки | на склейке главный элемент уже виден |
| HUD не читался на половине экрана | один цвет слоя поверх на разделённом экране | цвет по фону каждой половины |
| Хвост звука в чужой сцене | глитч 2–5 с из библиотеки тянулся через склейку | резать звук до следующей склейки (audio.md §6) |

## 6. Что проверяет человек

- **Звук на слух**: голос (живость, ударения, произношение терминов), музыка (подходит ли),
  баланс. Ассистент слышать не может — скажи это прямо и дай пути к файлам.
- **Лицензии** музыки и голоса (особенно для монетизируемых площадок).
- **Вкус**: стиль, персонаж, подача. Варианты — дешёвые: одна анимация, несколько дорожек.
