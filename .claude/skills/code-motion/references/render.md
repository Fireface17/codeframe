# Рендер и кодирование

Содержание: 1. Как устроен рендер · 2. Команды · 3. Motion blur · 4. Кодирование ·
5. Грабли и решения · 6. Сжатие и версии для площадок · 7. Проверка результата

## 1. Как устроен рендер

`render.mjs` открывает `index.html` в headless Chromium (Playwright), ждёт `window.READY`,
для каждого кадра вызывает `window.seek(t)` и снимает скриншот через CDP. Каждый кадр —
среднее SUB подкадров за затвор 180° (1/(2·FPS) с): ffmpeg `tmix` + `select`. Кадры идут
кусками в параллельные воркеры (у каждого свой браузер), куски кодируются в сырой H.264 и
склеиваются побайтово, затем упаковываются в MP4 с явной частотой кадров. Звук
подкладывается отдельно (`mux`), поэтому одну картинку можно выпустить с разными дорожками.

## 2. Команды

```bash
node render.mjs cues                                  # таблица T и длительность
node render.mjs sheet out/s.png 0.3,1,2,4 4           # контактный лист (время на каждом кадре)
node render.mjs still out/stills 1.5 3.2              # отдельные PNG
node render.mjs events out/events.json                # звуки для сведения
SUB=4 node render.mjs video out/draft.mp4 6           # черновик (быстро)
node render.mjs video out/master_v1.mp4 6             # чистовой мастер без звука
FROM=6 TO=9 node render.mjs video out/clip.mp4 6      # кусок для проверки
node render.mjs mux out/master_v1.mp4 audio/mix_vo.wav out/final/film_v1.mp4
QUERY=logo=mockup node render.mjs video ...           # вариант страницы через query
SCALE=2 node render.mjs video ...                     # настоящий 4K из той же раскладки
SUBMAP="9.3-10.1:40" node render.mjs video ...        # больше подкадров на быстрых участках (или window.SUBMAP_AUTO)
node render.mjs bench out/bench.json 2,5.5,9 8        # мс на подкадр (seek + растр + захват) в тяжёлых местах
node render.mjs det out/det 1.2,5.5,9                 # два свежих браузера, те же t: кадры побайтно равны?
READY_TIMEOUT=180 node render.mjs ...                 # ожидание window.READY (по умолчанию 90 с)
```
- `bench` — перед полным рендером: медиана × подкадры × кадры / воркеры ≈ время. Тяжёлое место
  (узорные заливки, WebGL) видно сразу.
- `det` — проверка детерминизма: второй прогон идёт в обратном порядке, кадр не должен зависеть
  от предыдущего. Обязательно после WebGL, частиц, кэшей.
- `SUBMAP` / `window.SUBMAP_AUTO = [[t0, t1, n]]` — на этих отрезках n подкадров вместо `SUB` (при
  `SUB ≥ 16`): проезды камеры и быстрые предметы без «стопки копий».
- Страница упала до `READY` — рендер не висит, а через 90 с выходит с ошибкой и сообщениями `pageerror`.
Весь цикл со звуком и проверками — `zsh tools/build.sh vN`.

## 3. Motion blur

- 16 подкадров на кадр, затвор 180°: размытие только там, где есть движение; статичные кадры
  не страдают. 4 подкадра — для черновиков: быстрые движения «ступенькой».
- Следствие: всё, что меняется за 1/120 с на стыке, усредняется. Кроссфейд двух текстов
  превращается в двойную экспозицию — уводи старое до входа нового (см. captions.js).
- Подкадры не должны пересекать жёсткую склейку: если склейка ровно между кадрами, ок; если
  посреди затвора — на одном кадре будет смесь двух сцен (обычно незаметно, но знай).

## 4. Кодирование

- x264 `-preset slow -crf 12 -tune animation -bf 0 -g 60`, `yuv420p`, BT.709 limited range.
  Белый плоский фон кодируется дёшево: битрейт выходит 3–8 Мбит/с даже при CRF 12.
- Звук: AAC 320 кбит/с, 48 кГц, `-movflags +faststart`.
- Площадки перекодируют всё сами — отдавай высокое качество, а не «под площадку».

## 5. Грабли и решения (все встречены на практике)

| Симптом | Причина | Решение |
|---|---|---|
| Кадров на 2 меньше в каждом куске | сырой H.264 с B-кадрами теряет первые кадры при упаковке в MP4 | `-bf 0` при кодировании кусков |
| После подкладки звука на 1 кадр меньше | `-shortest` режет по границе AAC-фрейма | не использовать `-shortest`, длины равны по построению |
| Потеря кадров на стыках MP4-кусков | concat MP4 c разными таймстемпами | куски в сыром H.264, склейка побайтово, упаковка с `-framerate` |
| `No such filter: drawtext` | сборка ffmpeg без freetype | подписи для листов рисуй на странице (`render.mjs sheet` так и делает) |
| `Maximum call stack size exceeded` | внутренняя функция названа `seek`, а `window.seek = t => seek(t)` | назови её `frame` |
| Сцена видна, хотя скрыта | `visibility="visible"` у потомков перебивает родителя | переключай сцены через `display` |
| Первые кадры без кириллицы | `document.fonts.load('40px X')` не грузит подмножества без пробела | `loadFonts()` грузит все FontFace |
| Плавающие пиксели в масштабированных вложенных сценах | частичная растеризация Chromium | `--disable-partial-raster` (включено) |
| Захват «ступеньками» по 16,7 мс | ограничение кадров Chromium | `--disable-frame-rate-limit` (включено, кадры идентичны) |
| ES-модули не грузятся | `file://` и CORS | классические скрипты (IIFE-сборки, `rough.js`; three.js — обёртка CJS или esbuild, `references/3d.md`). Importmap + `--allow-file-access-from-files` работает в рендере, но ломает превью по двойному клику |
| Числа NaN в трансформациях | `undefined` в длительности (часто — комментарий съел объявление в той же строке) | проверка: пройти по атрибутам на нескольких t и найти `NaN` |
| Рендер ушёл со старого кода | работа и рендер в разных копиях | одна папка; сверь время изменения файлов |
| Готовый файл исчез | перезапуск на тот же `--out` | версия в имени файла, сданное не трогать |
| После 100 % кадров файл ещё пишется | ffmpeg дописывает хвост | ждать строку `video: N/N frames`, проверять `ffprobe` |
| Субтитры смазаны | подкадры видят разное время | `caps.frame(Math.round(t * FPS) / FPS)` — субтитр по целому кадру |
| Быстрый предмет — «стопка копий» | 16 подкадров мало | `window.SUBMAP_AUTO = [[t0, t1, 40]]`; пролёт за 0,26 с при 48 подкадрах — чисто |
| Камера ступеньками | масштаб округлён до 3 знаков | 6 знаков в `transform` |
| Рендер висит | страница упала до `READY` | таймаут `READY` (90 с, `READY_TIMEOUT`) — встроен |
| Процесс не завершается после записи | браузер или ffmpeg держат node | `process.exit` после `browser.close()` — встроен |
| Узорные заливки (бумага, зерно) 67–128 мс на подкадр | дорогие паттерны SVG | запечь один раз в картинку слоя; `render.mjs bench` найдёт такие места |
| Пустые кадры в WebGL-сцене | скриншот снял очищенный буфер | `preserveDrawingBuffer: true` (`references/3d.md`) |

## 6. Сжатие и версии для площадок

- Instagram не принимает гигабайтные файлы. Рабочая команда для 1080p60:
  `ffmpeg -i in.mp4 -c:v libx264 -preset slow -crf 18 -maxrate 20M -bufsize 40M -profile:v high -level 4.2 -pix_fmt yuv420p -colorspace bt709 -color_primaries bt709 -color_trc bt709 -g 120 -c:a copy -movflags +faststart out.mp4`
- Новый звук к готовой картинке — без перерендера: `node render.mjs mux` (или `-c:v copy`).
- Отдельный SFX-слой и сжатие — отдельными шагами, не трогая мастер.

## 7. Проверка результата

```bash
ffprobe -v error -count_frames -select_streams v:0 -show_entries stream=nb_read_frames,r_frame_rate -of csv=p=0 out.mp4
```
`render.mjs video` сам сверяет число кадров с ожидаемым и пишет `FRAME COUNT MISMATCH`, если
что-то потеряно. Длительность MP4 = кадры / FPS; звук той же длины.
