# Музыка и звук для code-motion

Выбрать трек, подогнать под длительность ролика, свести голос, музыку и SFX. Пути не зашиты: SFX по умолчанию лежат в `../../assets/sfx` рядом со скриптами, `--sfx-dir DIR` подменяет папку.

Запуск: `uv run --script <скрипт>.py ...` (numpy и scipy ставятся сами). Нужен `ffmpeg` в PATH (Mac с Homebrew: `export PATH="/opt/homebrew/bin:$PATH"`). На входе любой формат, который читает ffmpeg (wav, mp3, ogg...), на выходе WAV 48 кГц стерео 16 бит.

> **Важно.** Синтезированные SFX звучат противно, берите записанные (foley, Kenney, Mixkit). Ассистент не слышит: всё ниже это измерения, а не слух. Финальный звук (музыку, SFX, баланс с голосом) обязательно слушает человек, и только после этого ролик готов.

| Скрипт | Что делает |
|---|---|
| `analyze.py` | метрики кандидатов: BPM, лад, мягкость, интро, концовка, «вокальность» |
| `vocal_check.py` | Whisper (mlx, нужен Apple Silicon): есть ли в треке вокал |
| `loop.py` | бесшовная петля ровно на D секунд (соцсети) |
| `edit.py` | нарезка под D с естественной концовкой (explainer, без петли) |
| `seam.py` | проверка шва петли (`loop.py` вызывает её сам; `--strict` даёт код 1 при CHECK) |
| `bars.py` | карта тактов: сетка, сильные доли, громкость и аккорд по тактам |
| `mix.py` | финальный звук: голос + музыка с дакингом + SFX |
| `sfx_make.py`, `sfx_analyze.py` | подготовка и метрики своих SFX (см. `../../assets/sfx/README.md`) |

## 1. Выбор трека

Где искать: Mixkit (Mixkit Free License), Pixabay Music (Pixabay Content License), CC0-коллекции (Free Music Archive, OpenGameArt, Freesound с фильтром CC0). Условия читайте на странице трека, источник и ID записывайте рядом с файлом. Файлы Mixkit в скилл не кладите: лицензия запрещает раздавать их отдельно; для остальных источников проверьте это сами.

Оценка без прослушивания:

```
uv run --script analyze.py трек1.mp3 трек2.mp3 --json an.json
uv run --script vocal_check.py трек1.mp3 [--language ru]
```

- `bpm`, `grid_ms`: темп и разброс ударов вокруг ровной сетки. У большинства из 36 проверенных Mixkit-треков 3..10 мс; 16 мс и выше (рубато, живая игра) значит ненадёжную сетку, резать такой трек по тактам рискованно.
- `key`, `m±`: мажор (m+) светлее минора (m-).
- `hf>4k`, `cen`: чем меньше, тем мягче и темнее звук (в тех же треках hf>4k от 0.3 до 11 %).
- `pcrest`, `onpk`: чем выше, тем резче ударные и колючее ритм.
- `intro`, `first30`: длина тихого вступления и громкость первых 30 с. `edit.py` стартует с первого неглухого такта, длинное интро займёт начало explainer; петле это безразлично, `loop.py` берёт такты из середины трека.
- `end`: как заканчивается сам трек: `ring` (затухающий финальный аккорд), `fade` или `cut`; для `edit.py --end ring` нужен именно `ring`.
- `voc`: заметно выше медианы партии значит проверить `vocal_check.py`. Вердикт `VOCALS LIKELY` означает связные слова с низким `nsp`; у инструментала будут пустые сегменты или мусор с высоким `nsp`.

Ориентир, трек прошёл в рилс: 115 BPM, grid ±6.8 мс, D major, hf>4k 3.0 %, cen 210 Гц, intro 1.0 с, LRA 3.4, вокала нет. Это ориентиры, не пороги.

## 2. Подгон под длительность

Соцсети, ролик зациклен: D = `duration` из `events.json`.

```
uv run --script loop.py трек.wav out/music.wav 17.0
```

Целое число тактов (6..12), темп подтягивается atempo до ±7 % (`--max-stretch`), старт на ударе в t = 0, без фейдов. Из лучших кандидатов выбирается тот, у которого шов (`seam.py`) чище, вердикт OK/CHECK печатается сразу. Рядом ляжет `out/music.plan.json`: сетка долей во времени фильма для синхрона анимации.

Explainer, без петли: естественная концовка.

```
uv run --script edit.py трек.wav out/music.wav 45.0 [--end auto|ring|fade]
```

Старт на сильной доле с fade-in 0.35 с, не больше одного прыжка между тактами. `ring`: финальный аккорд затухает сам; `fade`: плавный уход на тонике; `auto` выбирает сам. Вручную: `--plan "f0:f1:s0,..."`. Рядом тоже ляжет `.plan.json`.

Энергичный монтаж — **с дропа**: старт на сильном такте после нарастания, без fade-in, первая сильная доля — на первой склейке.
`bars.py трек.wav` покажет такты и громкость; дальше `edit.py трек.wav out/music.wav D --start-bar N --fade-in 0 --end auto`
или вручную `--plan 0:D:<секунда доли в треке> --fade-from <D − 1,2>`. В `build.sh` проекта: `MODE=edit EDIT_ARGS="--start-bar N --fade-in 0"`
(в `EDIT_ARGS` подстрока `:D:` заменяется длиной фильма), `LOOP_ARGS` — флаги `loop.py`, `MIX_ARGS` — флаги `mix.py`
(под бит: `--bed-rel -1.5 --duck 5`, голос − музыка 5–7 LU). Готовую ручную нарезку build.sh не трогает: `MUSIC_CUT=out/music_drop.wav`.

## 3. events.json

```json
{"duration": 17.0, "events": [{"t": 0.35, "name": "hit"}, {"t": 6.0, "name": "scribble", "gain_db": -1}]}
```

Это формат `node render.mjs events <файл>`; допустим и голый список событий. `t` секунды киновремени, `gain_db` необязателен. `name` это класс (`hit`, `thud`, `paper`, `whoosh`, `scribble`, `boom`, `mech`): `hit` по очереди берёт `hit_1`, `hit_2`... и не повторяет один вариант подряд, `hit_2` задаёт вариант. Подойдёт любой `<имя>_<n>.wav` из папки SFX. Необязательное поле `cuts` (времена склеек; `render.mjs events` пишет его, если фильм выставил `window.CUTS`) включает проверку: звук, чей слышимый хвост заходит за следующую склейку, mix.py печатает с `WARNING`.

## 4. mix.py

```
uv run --script mix.py MUSIC.wav|- VO.wav|- EVENTS.json|- OUT.wav [--no-music] [--lufs -14] [--tp -1] [--sfx-dir DIR]
```

| MUSIC | VO | Результат |
|---|---|---|
| файл | файл | голос + музыка с дакингом + SFX |
| файл + `--no-music` | файл | голос + SFX (версия под трендовый звук в приложении) |
| `-` | файл | то же, что `--no-music`, но явно |
| файл | `-` | музыка + SFX, без дакинга (ролик без озвучки) |
| `-` | `-` | ошибка, нечего сводить |

`EVENTS.json` вместо файла можно заменить на `-` (без SFX).

- Длительность выхода: `--dur`, иначе `duration` из `events.json`, иначе самый длинный вход (файл музыки считается и при `--no-music`). Музыка добивается тишиной или обрезается (20 мс fade-out); петля, расходящаяся на пару сэмплов из-за округления D, остаётся как есть.
- Громкость: `--lufs -14` для соцсетей (по умолчанию), `--lufs -16` для explainer (обычно с `--bed-rel -5`, музыка тише голоса на 5 LU вместо 3.5). `--tp -1`: true peak не выше -1 dBTP (по умолчанию; для explainer можно `-1.5`).
- Дакинг: музыка опускается на 9 dB (`--duck`, диапазон 8..10) под речью, атака 80 мс (`--attack`), релиз 400 мс (`--release`), удержание 120 мс и упреждение 80 мс; в паузах и до/после голоса музыка возвращается.
- SFX ставятся от голоса, а не от пика файла: самое громкое окно 200 мс на 6 dB ниже речи (`--sfx-rel`) плюс поправка класса (hit 0, thud -1, paper -2, whoosh -2, scribble -3, boom -2, mech -4 dB; старые имена pop/tick/click/ding из прежних папок проектов сохраняют свои поправки) и `gain_db` события; пик ограничен, повторы подряд тише на 1.5 dB. Голос и SFX проходят через одну небольшую «комнату», чтобы записи не звучали наклеенными. Без голоса опорой служит музыка.
- Прочее: `--stems` (рядом `.music/.vo/.sfx.wav`), `--vo-offset`, `--no-room`, `--room-vo`, `--room-sfx`; всё: `mix.py --help`.

Проверка результата (в строке `I:` целевой LUFS, в `Peak:` не выше -1):

```
ffmpeg -nostats -i out/mix.wav -af ebur128=peak=true -f null - 2>&1 | grep -E "^ +(I|Peak):"
```

Для build.sh (`AUDIO` папка `scripts/audio` скилла):

```sh
D=$(node -e "console.log(require('./out/events.json').duration.toFixed(4))")
uv run --script "$AUDIO/loop.py" "$TRACK" out/music.wav $D
uv run --script "$AUDIO/mix.py" out/music.wav audio/vo.wav out/events.json out/mix_vo.wav
uv run --script "$AUDIO/mix.py" out/music.wav audio/vo.wav out/events.json out/mix_novo.wav --no-music
```
