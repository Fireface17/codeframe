# Форматы выдачи

## 1. Двухколоночный сценарий (по умолчанию)
Таблица: время, голос (то, что звучит), экран (картинка / текст на экране / звук). В конце — итог.

Пример ниже — из ниши моушн-дизайна; структура одна для любой темы.

```markdown
**Ролик:** «<рабочее название>» · жанр · площадка · ~30 с
**Одна мысль:** …
**Финальная фраза:** …

| Время | Голос | Экран: картинка / текст / звук |
|---|---|---|
| 0–2 | «Эта анимация стоит пять тысяч. А эта — пятьдесят.» | Две одинаковые плашки едут вправо. Текст «5 000 / 50 000». Щелчок |
| 2–5 | «Разница не в дизайне. В одной кривой.» | Плашки замирают, между ними рисуется график. «1 КРИВАЯ» |
| 5–11 | «Слева скорость постоянная. Так не движется ничего: ни машина, ни рука.» | Линейный график; машинка дёргается на старте и стопе |
| 11–18 | «Но добавьте разгон и торможение — и мозг читает это как вес.» | Кривая изгибается, плашка «тяжелеет». «РАЗГОН → ВЕС» |
| 18–25 | «Поэтому дорогие ролики почти не двигаются линейно. Даже текст.» | Быстрая нарезка: логотип, кнопка, буквы с ease-out |
| 25–30 | «Посмотрите на свой последний ролик. Сколько там прямых?» | Прямые на графике краснеют. Последний кадр = первый (петля) |

**Итог:** 62 слова · 30 с · 2,1 слова/с (спокойно; для бодрой подачи 2,8 сл/с — ~84 слова) · повторный хук на 11 с («Но…»)
**Проверить:** —
```

Для съёмки «говорящей головы» колонка «Экран» = план (крупный/средний), жест, вставка, надпись.

## 2. script.json для code-motion (если установлен)
Раздел нужен, только если ролик делается кодом и установлен навык `code-motion`; без него пропусти.
Если ролик делается кодом, выдай `script.json` — по нему идёт озвучка, тайминг
слов и субтитры. Одна фраза сценария = одна запись `phrases`.

```json
{
  "lang": "ru",
  "lead": 0.3,
  "tail": 0.6,
  "pauses": [0.28, 0.3, 0.3],
  "phrases": [
    { "display": "Эта анимация стоит 5000. А эта — 50000.",
      "tts": "Эта анимация стоит пять тысяч. А эта — пятьдесят тысяч.",
      "align": "Эта анимация стоит пять-тысяч. А эта — пятьдесят-тысяч." },
    { "display": "Разница не в дизайне. В одной кривой." }
  ]
}
```
Правила полей:
- `display` — текст субтитров (что видит зритель), с пунктуацией; цифры допустимы.
- `tts` — что произносит голос: числа словами, «Афтер Эффектс» вместо «After Effects», ударения «+»
  или U+0301. Нет поля — берётся `display`.
- `align` — текст для выравнивания, **только кириллица** для `ru`. **Число слов в `display` и `align`
  каждой фразы должно совпадать** (слово = кусок между пробелами с буквой или цифрой; одинокое тире
  не слово). Несколько слов под одно слово экрана склей дефисом: «пять-тысяч». Нет поля — берётся `display`.
- `pauses` — тишина между фразами, с; на одну меньше, чем фраз. После «ага»-момента — 0,5–0,8.
- Числа в `display` пиши без пробелов-разделителей («5000», не «5 000»): пробел делает из числа два слова.
- Проверь сам перед выдачей: посчитай слова `display` и `align` в каждой фразе.

## 3. Список шотов для генерации (например, Higgsfield)
Генерируемым шотам нужен отдельный план, потому что текст и логотипы модели рисуют плохо, а сложные
движения камеры ломаются. Для каждого шота:

```markdown
| # | Время | Ключевой кадр (картинка) | Движение (одно) | Промпт видео | Длина/формат | Поверх (кодом/в монтаже) |
|---|---|---|---|---|---|---|
| 1 | 0–3 | макро: рука на клавиатуре, неон монитора | slow push in | субъект → окружение и свет → камера → настроение | 5 с, 9:16, 720p черновик → 1080p | заголовок «ОДНО ТЗ» |
```
Правила: сначала ключевой кадр (изображение), потом image-to-video; одно движение камеры на шот;
никакого текста, логотипов и рук с предметами крупно; персонаж между шотами — через функцию постоянного
персонажа сервиса (в Higgsfield — Soul ID / Elements);
«что не должно меняться» — отдельной фразой в промпте. Текст и графика — поверх, кодом или в монтаже.

## 4. Карусель из того же сценария
Обучающий ролик почти всегда превращается в карусель-шпаргалку — её сохраняют и показывают повторно.
- Слайд 1 — хук ролика (обложка), 3–7 слов, крупно.
- Слайды 2…N−1 — по одному биту/шагу на слайд, одна мысль, цифра или схема.
- Последний слайд — вывод + один призыв: «сохрани» (по умолчанию для карусели) или польза по слову.
- 5–10 слайдов, формат 1080×1350 (4:5) или 1080×1440 (3:4).

## 5. Лист для записи своим голосом (`*.zapis.md`)
Если голос живой, к сценарию нужен отдельный лист — по нему автор читает, не думая о разметке.
Сохраняй рядом со сценарием: `content/scripts/<дата>-<slug>.zapis.md`.
- **Как читать** (шапка листа): КАПС — главное слово фразы, чуть медленнее и с микропаузой перед ним
  (выделяет пауза, а не крик); `|` — короткая пауза без вдоха; `↘` — интонация вниз, утверждение;
  `→` — ровно, «продолжение следует» (на запятой, тире, двоеточии); ударения в трудных словах — заглавной
  гласной (смотр**И**, нарис**О**ванного) и как читать латиницу («Claude» — «Клод»); темп — 2,7–3 сл/с,
  концы фраз не ускорять.
- **Дубли:** каждую фразу 3 раза подряд — спокойно → чуть ярче → ещё ярче; между дублями 1 с тишины,
  между фразами 2–3 с. Монтажёр (или скрипт) выберет лучший.
- **Перед записью** (2 мин): скороговорка 3 раза, потом с карандашом поперёк зубов, потом снова без;
  глоток воды; встать, чуть улыбнуться; микрофон или ноутбук сбоку под углом, 25–30 см от рта (меньше
  свиста на «с» и «ш»).
- **Текст:** нумерованные фразы, под каждой — курсивом одна подсказка к подаче.

```markdown
3. Но картинку можно не РИСОВАТЬ. → | Её можно ПОСЧИТАТЬ. ↘
   *Противопоставление: оба слова главные, «ПОСЧИТАТЬ» сильнее и вниз.*
```
После склейки дублей свистящие «с/ш» стоит приглушить диэссером до сведения.
